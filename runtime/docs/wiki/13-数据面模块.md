# runtime-data 模块

> 包路径：`com.ww.runtime.data` ｜ 源码：`runtime/data/src/main/java/com/ww/runtime/data/`（57 个主类：顶层 2 + cache 8 + cache/engine 20 + storage 11 + storage/engine 16）
> 定位：**数据面能力实现层**——CACHE（Redis 风格缓存）与 STORAGE（S3 风格对象存储）两种 Capability 的真实实现，含引擎、网关路由、跨节点转发、写后复制与迁移适配。
>
> **修订注记（2026-10-20）**：①`StorageCapability` 增**分区写冻结**（`freezePartition`，TTL 自愈，迁移 cutover 用）与**落盘后二次 `checkOwner`**（长流式写跨越 cutover/冻结时不应答）；②副本删除带**版本护栏**（`replicaDelete(bucket,key,version)`，副本版本更高拒删）；③`putReplica` 同版本异 etag 改为**主端权威覆盖**（旧「保留先到」使分叉永不可修复）；④`reconcile` 新增 **prune 阶段**（删除副本上本机权威分区已不存在的僵尸对象，删除带版本护栏；需 `PlacementView.holdersAll` + `isAuthoritativePrimary`）；⑤`isReplicaLagging` 版本相等时比对 **etag**；⑥`awaitDrained` 复制排空屏障（挂 `CapabilityManager` 冻结前钩子，排空前先追平副本，P1-3）；⑦半同步复制**默认开启**（`RuntimeProperties` `RUNTIME_CAPABILITIES_STORAGE_SEMI_SYNC_ENABLED`，默认 true）。

## 1. 模块职责与依赖

- 实现 `CapabilityModule` SPI：`CacheCapability`（type=CACHE）、`StorageCapability`（type=STORAGE）；
- 实现 `PartitionDataAdapter` SPI：`CachePartitionAdapter`、`StoragePartitionAdapter`（分区导出/导入/清理/压实），经 `CompositePartitionAdapter` 按能力分发，供 migration 模块搬运；
- 网关（`CacheGateway`/`StorageGateway`）：任意节点接入、按 PlacementView 路由到属主（本地直连或 gRPC 转发，StaleEpoch 重查属主重试一次）；
- 复制（`StorageReplicator`）：STORAGE 写后异步复制到 REPLICA + backlog 重放 + 周期对账；
- 依赖：`runtime-common`、`runtime-capability`（SPI/PlacementView）、`runtime-migration`（PartitionDataAdapter）、`runtime-placement`（Partitioner 口径）、`runtime-proto`（cache/storage 契约）+ Jackson 3（元数据 JSON）+ slf4j；
- **零 Spring**（enforcer 门禁同核心模块）；不直接依赖 cluster——节点目录经 `CachePeerDirectory`/`StoragePeerDirectory` 端口由宿主用 NodeRegistry 适配。

**三层结构**：

```
HTTP 端点（server: /cache/* /storage/*）
   ▼
网关层（CacheGateway / StorageGateway）── PlacementView.owner/holders 路由
   ▼                     └─ 非属主 → CacheGrpcClient / StorageGrpcClient 转发
能力层（CacheCapability / StorageCapability）── fencing（属主校验）+ frozen 门 + 迁移 API
   ▼
引擎层（cache/engine: SimpleCache+StreamStore+AOF ／ storage/engine: ObjectStore+Drive 盘阵）
```

## 2. CACHE 数据面

### 2.1 能力与网关

| 类 | 要点 |
|---|---|
| `CacheCapability` | 构造 `(self, view, partitioner, aofEnabled, aofDir[, aofRewriteBufferMaxBytes])`。**start**：建 `SimpleCache` + `StreamStore`；AOF 开启时先 `AofService.start() → replay(cache)` 再挂 aof（回放期不挂，防重启翻倍写）。**fencing**：`put/putIfAbsent/remove` 前校验属主==self（无放置/异主 → `StaleEpochException`；frozen → `"frozen"`）；读不 fencing；`putIfAbsent` 在属主端原子判存。TTL 约定：>0 相对毫秒、<=0 永不过期。迁移面：`exportPartition`（KV/Hash/List/Set/ZSet/Stream 全类型、(key,kind) 稳定排序）、`importPartition`（整 key 替换幂等）、`clearPartition`/`retainPartitions`（C30 分批）、`compactAof`。管理面：`listKeys`/`countKeys`/`totalItems` |
| `CacheGateway` | put/putIfAbsent/get/remove 查 `view.owner(CACHE, partition)`：无放置或属主=self 走本地，否则 `CacheGrpcClient.forwardXxx`；`StaleEpochException` 重取属主**重试一次**。管理面 fan-out：`listKeys`（专用 `cache-fanout` 池，4 线程/队列 256/35s 超时；peer 取 `directory.servingPeers()`——CACHE actual=ACTIVE ∩ 存活；合并按 key 去重取 **TTL 较小者**）、`countKeys`（求和）、`deleteKeys`（并行逐 key 路由，C28）。client/directory=null 退化本地单机 |
| `CacheGrpcServer` / `CacheGrpcClient` | cache.proto 的 6 个 RPC：`ForwardPut/ForwardPutIfAbsent/Get/Delete`（属主端 fencing）、`ListKeys`（未启动回空流）、`CountKeys`。服务端 `forwardGet` 先 `servesPartitionOf` 纠偏，非属主回 `ABORTED "not-owner"`（网关据此重路由重试）。错误映射：stale-epoch→ABORTED、frozen→UNAVAILABLE、其余 INTERNAL。客户端通道 8MB 上限（C27）、deadline 30s、按 target 缓存 |
| `CachePartitionAdapter` / `CacheChunkCodec` | 迁移分片行格式 **v2**：`key + 0x01 + kind字符(K/H/L/S/Z/T) + 0x01 + ttl + 0x01 + base64(payload) + 0x02`，一条目一分片惰性导出；不兼容 v1。`CachePartitionEntry` 携带各容器类型快照（Stream 快照含消费组/PEL） |
| `CachePeerDirectory` | 端口：`endpoint(node)`、`alivePeers()`、`servingPeers()`（default=alivePeers，宿主按能力过滤） |

### 2.2 cache/engine（Redis 风格引擎，内化自原 common/cache）

- **SimpleCache**（implements `Cache`）：ConcurrentHashMap 存储 + **LRU**（access-order，默认上限 10 万，驱逐联动 versions/zset 索引）+ 条带锁（64）保护集合建/写 TOCTOU；类型覆盖观察计数（C24）；`putIfAbsent` 以 `compute` 原子判存，仅实际写入才记 AOF/bump 版本（事务内同样按结果提交）。
  - 数据结构：KV、Hash、List、Set、**ZSet**（ConcurrentSkipListMap 分数索引 + 成员反向索引，五删除路径统一清理 C8）、Stream（门面委托 StreamStore）；
  - TTL：相对/绝对/容器级、惰性过期 + 周期驱逐调度；
  - 防击穿/穿透：`getWithLoader` per-key 锁 + 60s 空值缓存（C9/C42）；
  - 事务：MULTI/EXEC/DISCARD/WATCH（进程内版本乐观锁；远端写经显式版本同步）；
  - 批量：`removeMany`（AOF REMOVE_MULTI 聚合）。
- **StreamStore**：每 stream 一个跳表（O(log n) 范围操作）；xadd（AUTO/显式 ID、MAXLEN trim）、阻塞 xread（waiters 唤醒、32 并发许可超限降级非阻塞）、消费组全套（xreadGroup/xack/xclaim/xautoclaim/xpending/xinfo）、PEL 上限拒绝计数；Raw 系方法专供 AOF 回放（不再落日志）。
- **AofService**：二进制 AOF（当前 **v2 格式 "AOF2"**，v1 存量兼容读、首次重写后升级）；记录体 CRC32 校验（损坏截断止血 C5）；fsync 三策略 always/everysec/no（C4 真实生效）；bgRewrite 双写缓冲（C3 换文件窗口分离、C12 超限**中止不丢写**、原子 rename）；回放：毒记录跳过计数、bulk 记录（XADD_BULK/REMOVE_MULTI）仅 v2。观测：`getStatus()` 与各类计数器。
- **Codec**：值类型标记编码（NULL/STRING/INT/LONG/DOUBLE/BOOL/容器/OBJECT）；反序列化 JEP290 白名单 + gadget 黑名单（**默认 dry-run 只计数不拒绝**）。
- **AofProperties/AofFormat**：参数对象与格式常量（操作码 34 种、`MAX_KEY_BYTES=65535`、超长 key 拒绝 C34）。

## 3. STORAGE 数据面

### 3.1 能力、网关与复制

| 类 | 要点 |
|---|---|
| `StorageCapability` | 分区口径 `partitioner(bucket + "/" + key)`。**start**：组装引擎（DriveManager→SetLocator→ObjectStore→BucketStore）+ `rebuildIndex()` + ImportAggregator + T11 临时文件清扫/周期 GC 线程。**写路径** `putObject`：属主 fencing + `SizeLimitedInputStream` 兜 maxObjectSize + 写穿元数据缓存 + 成功后触发 `WriteHook`（本地直写与 ForwardPut **统一触发**——复制器即挂此钩子）。副本面 `replicaPut/replicaDelete` 不做 fencing、version 防回退。迁移面：exportPartition（对象按 chunkSize 切片）、importChunks（ImportAggregator 流式聚合）、retainPartitions、deletePrefix、countObjects |
| `StorageGateway` | 写路由同 CACHE（本地 fencing 拒→重查重试一次；**远端 ForwardPut 的拒折不重试**——上行流已部分消费，直接 409）。区间读 `get(offset,length)` 属主端窗口化回传，旧版属主全量回退时网关按片快进丢弃（零拷贝）。`list` fan-out servingPeers 单页合并：同 key 取最高 version、**属主结果为准剔除复活副本**（T20）、失败节点记 missingPeers 降级（T19）。`createBucket` 本地+SyncBucket 广播；`deleteBucket` **远端先行**（集群级空判定 + 各 peer 确认后才删本地，T10）。`reconcileBuckets`（T21 桶名比差补建） |
| `StorageReplicator` | 写后异步复制（implements WriteHook）：`view.holders()` 取 REPLICA，虚拟线程并行 `Replicate/ReplicateDelete`（主预计算 etag/version，副端不重算；删除携带版本护栏）。失败入有界 backlog（10k，满淘汰最旧、同对象去重；条目含版本），`storage-replicator-replay` 线程 5s 起指数退避重放——**重放以当前本地状态为准重建意图**（本地对象存在→复制当前版本；已删→带版本墓碑删除），且重放前校验本机仍是权威属主（P1-7）；`reconcile` 每 5min 扫本机 PRIMARY 分区经 `remoteList` 摘要分页比对补齐 + **prune 僵尸副本**（P1-5，`holdersAll` 枚举含整分区删除场景；删除带版本护栏）；`awaitDrained(timeout)` 排空屏障（在途 + backlog 强制重放，freeze(true) 前调用）。**backlog 仅进程内，对账是全量兜底** |
| `StorageGrpcServer` | storage.proto 10 RPC。流式接收用 `IngestObserver`：回调线程 → 有界队列(8) → **虚拟线程落盘**，队列满即背压、60s 超时防钉死（C32 修复线）；oversize 早期拒绝 |
| `StorageGrpcClient` | 通道上限 `chunkSize+1MB`；流 deadline 1h；管理面失败降级空/false，strict 变体（countKeysStrict/countObjectsStrict）上抛供退役预检区分宕机与空 |
| `ImportAggregator` | 迁移导入暂存（T1）：按 aggKey FileChannel 流式追加 `.mig` 文件（零堆内聚合）；偏移不连续中止、finish 校验 size、启动清扫残留、周期 sweepStale |
| `StoragePeerDirectory` | 同 Cache 端口语义，servingPeers=STORAGE actual=ACTIVE ∩ 存活 |

### 3.2 storage/engine（内化自原 common/storage）

```
Drive（一块盘/目录根）
  └─ StorageSet（一组 Drive，条带；预留纠删码位）
       └─ SetLocator：SHA1(bucket\0key) → setIndex % setCount → drive（本地选盘，与集群 placement 正交）
            └─ ObjectStore（putPrimary/putReplica/get/head/delete/list/countObjects/rebuildIndex…）
                 ├─ MetadataIndex（内存有序索引，容量超限按桶降级目录扫描，T22 generation 代数）
                 ├─ ObjectMetadataCache（写穿，仅本地主视角）
                 ├─ ByteBufferPool（直接内存 + 许可制硬上限，超时抛）
                 └─ CryptoCodec（接口 + Identity 透传实现，加密预留）
```

- 落盘布局：`buckets/<bucket>/.bucket` + `objects/ab/cd/<sha1>/{object.data, object.meta}`（二级散列）；写流程 **tmp 先 rename .data 再 rename .meta**（元数据可见=数据完整）；流式写同步算 MD5=ETag（明文指纹，与加密正交）；同 (bucket,key) 64 条带锁保 version 单调。
- `putReplica`：主端算好的 etag/version 直接落；version 更高拒收（防回退）；**同版本同 etag 幂等跳过、同版本异 etag 主端权威覆盖并计数告警**（P1-6）。
- `ReadHandle`：本地文件句柄可走 Servlet sendfile 零拷贝；观测计数 sameVersionConflicts（t26）/corruptedMetaQuarantined（t15）。
- `StorageProperties`：rootDir/drives/drivesPerSet(0=自动)/maxObjectSize(引擎默认 1GB；宿主键默认 50GiB)/metadataIndexMaxEntries/importStaging*/strictBucketCheck/replicaSkipFsync/tempSweep* 等。

## 4. 顶层协作类

| 类 | 说明 |
|---|---|
| `CompositePartitionAdapter` | `PartitionDataAdapter` 多能力组合：按 capability 大写查表分发（MOCK/CACHE/STORAGE），未注册抛 MigrationException；暴露 `capabilities()` 供 PartitionSweeper 遍历 |
| `GatewayErrors` | Cache/Storage 网关共享 gRPC 错误→异常映射（stale-epoch/not-owner→StaleEpochException(409)；frozen→423；其余 503）；`isReroutable()` 判定可重路由 |

## 5. 与其他模块的关系

- 被 server 装配（数据面全部 Bean）；被 migration 的 SPI 约束（实现 `PartitionDataAdapter`）；
- 消费 capability 的 `PlacementView.owner/holders`（fencing/复制选点）与 common 的 `Partitioner` 同口径哈希；
- 与 scheduler 无编译依赖——副本数据补齐走本模块 Replicator，**不占用 MigrationEngine**。
