# runtime-cluster 模块

> 包路径：`com.ww.runtime.cluster` ｜ 源码：`runtime/cluster/src/main/java/com/ww/runtime/cluster/`（13 个主类，含 `decommission` 子包 5 类）
> 定位：**集群控制——节点生命周期状态机 + 集群节点目录 + 退役记录存储**。

## 1. 模块职责

- 定义节点状态机（JOINING/ACTIVE/SUSPECTED/LEAVING/DEAD）的合法跃迁规则（含反向索引 `legalPredecessors`）；
- 提供节点注册表抽象 `NodeRegistry` 及两种实现：进程内 `InMemoryNodeRegistry`（ConcurrentHashMap）与 PostgreSQL 的 `JdbcNodeRegistry`（plain SQL + 单语句 CAS）；
- 提供多级故障确认的怀疑票存储 `NodeSuspicionStore`（`InMemoryNodeSuspicionStore`/`JdbcNodeSuspicionStore`，表 `rt_node_suspicion`）：membership 投/撤票，scheduler leader 计票仲裁；
- 封装单节点运行时 `NodeRuntime`：注册 → 启动 gRPC 宿主 → 自检 → ACTIVE → 采样/心跳双线程 → 优雅退出；误判 DEAD 可 `reRegister()` 复活；
- 采集本机 CPU/内存/磁盘指标（`ResourceMonitor`/`OsResourceMonitor`）；
- `decommission` 子包：节点退役记录存储（`rt_decommission` 表，状态机 DRAINING→REMOVING→COMPLETED/FAILED），推进逻辑在 scheduler/server；
- `ClusterSchema` 幂等初始化数据库表。

## 2. Maven 坐标与依赖

- 坐标：`com.ww:runtime-cluster:1.0-SNAPSHOT`
- 依赖：`runtime-common`、`runtime-proto`、slf4j-api；测试 junit/assertj
- 构建门禁：enforcer 禁 Spring/JPA/Caffeine。JDBC 实现仅用 JDK 自带 `javax.sql.DataSource`，不绑定驱动与连接池（由宿主注入）。

## 3. 关键类详解

### 3.1 NodeStateMachine（final 工具类，纯静态）

节点生命周期的**静态合法跃迁表**：

```
JOINING  → {ACTIVE, DEAD}
ACTIVE   → {SUSPECTED, LEAVING, DEAD}
SUSPECTED→ {ACTIVE, DEAD}
LEAVING  → {DEAD}
DEAD     → {JOINING}         （唯一出边：重新 register/reRegister 复活）
```

| 方法 | 行为 |
|---|---|
| `static void check(NodeState from, NodeState to)` | 非法跃迁抛 `IllegalStateTransitionException`（消息含 `from -> to`）；null 参数抛 NPE |
| `static Set<NodeState> legalPredecessors(NodeState to)` | **反向索引**（PREDECESSORS 表）：枚举某目标态的合法前驱集合，供 `JdbcNodeRegistry.markState` 拼 `WHERE state IN (...)` 单语句 CAS |

### 3.2 NodeRegistry（接口，实现必须线程安全）

| 方法 | 语义 |
|---|---|
| `void register(NodeInfo)` | **upsert**：无论此前状态，一律重置为 JOINING 且 state_epoch=0（节点重启恢复语义） |
| `void heartbeat(NodeId, ResourceSnapshot)` | 刷新心跳时间与资源快照（心跳时刻取 `snapshot.updatedAtMillis()`）；未知节点抛 IAE |
| `void markState(NodeId, NodeState)` | 经状态机校验后跃迁且 `state_epoch + 1`；非法抛 `IllegalStateTransitionException` |
| `Optional<NodeInfo> get(NodeId)` | 查单节点 |
| `List<NodeInfo> listAlive()` | 过滤 DEAD 与 LEAVING 的存活视图 |
| `List<NodeInfo> listAll()` | 全量视图（含 DEAD 墓碑行，按 node_id 排序） |
| `void tombstone(NodeId)` | 置 DEAD 并保留行，幂等 |

> 接口未新增方法（无 updateWeight/listByStates 等）——权重等扩展经 `register` upsert 完成。

### 3.3 InMemoryNodeRegistry

- `ConcurrentHashMap<NodeId, NodeInfo> nodes`；所有"存在性检查 + 派生替换"在 `nodes.compute` 的原子语义内完成（compute 内抛异常则 map 不变）。
- `register` 强制重置 JOINING/epoch 0；`tombstone` 幂等（已 DEAD 不再前进 epoch，未知节点静默 no-op）；`heartbeat` 未知节点抛 IAE。

### 3.4 JdbcNodeRegistry（PostgreSQL 方言，plain SQL）

| 方法 | SQL 行为要点 |
|---|---|
| `register` | `INSERT ... ON CONFLICT (node_id) DO UPDATE`：强制 `state='JOINING'`、`state_epoch=0`；registered_at 取**数据库时钟** `(EXTRACT(EPOCH FROM NOW())*1000)::BIGINT`；resources_at/heartbeat_at 均绑 `snapshot.updatedAtMillis()`；zone 随注册行 upsert（`NodeRuntime.withZone`/`RUNTIME_NODE_ZONE`） |
| `heartbeat` | `UPDATE rt_node SET cpu/mem/disk..., resources_at=?, heartbeat_at=? WHERE node_id=?`；命中 0 行抛 IAE |
| `markState` | **S9 单语句 CAS + 最多 8 次重试**：按目标态从预生成 SQL 表（EnumMap，合法前驱内联为 `WHERE node_id=? AND state<>? AND state IN (<legalPredecessors>)`）执行 `SET state=?, state_epoch=state_epoch+1` → 命中 0 行时读回一次：同态→`IllegalStateTransitionException`、前驱非法→抛、合法但 0 行=并发竞态→重试；连败 8 次抛 `RuntimeFrameworkException("lost update race 8 times")` |
| `listAlive` | **专用 SQL** `WHERE state NOT IN ('DEAD','LEAVING') ORDER BY node_id`（不再内存过滤 listAll） |
| `tombstone` | `UPDATE ... SET state='DEAD', state_epoch=state_epoch+1 WHERE node_id=? AND state<>'DEAD'`（幂等，不检查行数） |
| `mapRow` | NULL 兼容：cpu_percent null→0.0；resources_at null→回退 registered_at；字节列 null→0；updatedAt=max(0,…) |

### 3.4b NodeSuspicionStore（接口，多数仲裁凭据层）

- 语义：`(suspect, observer)` 复合主键，一张票一行；`vote` upsert 刷新 φ 与时间戳，`recall` 撤票（幂等），`freshVoteCount/freshVoteCounts` 按 TTL（`updated_at >= now-ttl`）统计**不同观察者**数，`clear(suspect)` 判死后收敛，`pruneExpired` 周期清扫；
- `InMemoryNodeSuspicionStore`：`suspect -> (observer -> Vote(phi,ts))` 双层 ConcurrentHashMap，注入 Clock；
- `JdbcNodeSuspicionStore`：INSERT … ON CONFLICT DO UPDATE 投票、GROUP BY 计票；SystemClock 走数据库时钟（S14 同款分支），注入时钟走本地时间；
- 写压力：仅 SUSPECTED/DEAD 期间每检测周期每观察者一行 upsert，健康态零写入；量 O(故障节点数 × 观察者数)。

### 3.5 ResourceMonitor（接口）与 OsResourceMonitor

- 接口：`ResourceSnapshot snapshot()`。
- `OsResourceMonitor(File dataDir, Clock clock)`：基于 `com.sun.management.OperatingSystemMXBean` 与 `File.getTotalSpace/getUsableSpace`。
- 采集逻辑：
  - CPU：`getCpuLoad() * 100`，`clampPercent` 收敛 [0,100]（不可用的 -1 → 0.0）；
  - 内存：total−free，均 `max(0, ...)` 防负；
  - 磁盘：dataDir 所在卷 total−usable；
  - 采样时刻：`clock.nowMillis()`（可注入 TestClock）。

### 3.6 NodeRuntime（单节点运行时）

字段：self/host/configuredGrpcPort/weight/registry/grpcHost/monitor/clock/heartbeatIntervalMs；`AtomicBoolean started/shutdown`；`volatile ScheduledExecutorService` 心跳线程 + 采样线程；`volatile ResourceSnapshot latestSnapshot`（S13 采样缓存）；常量 `SELF_CHECK_TICKS = 5`。

| 方法 | 行为 |
|---|---|
| `synchronized start()` | ① 初始快照入 `latestSnapshot` → ② `registry.register(JOINING, epoch 0)` → ③ 未运行则 `grpcHost.start(port)` → ④ 随机端口场景以实际端口**再次 register** → ⑤ 自检（isRunning && port>0，失败抛 `IllegalStateException("gRPC self-check failed")`）→ ⑥ `markState(ACTIVE)`（epoch 0→1）→ ⑦ 启动采样线程 + 心跳线程 → ⑧ started=true。**失败回滚（深审6）**：③~⑥ 任一步异常 → 仅当本路径启动过 host 才 stop + `registry.tombstone(self)`（防 JOINING 孤儿），原异常重抛（失败清理异常 addSuppressed） |
| `int grpcPort()` | 宿主运行时返回绑定端口，否则返回配置端口 |
| `synchronized reRegister()` | **S2 复活入口（public）**：DEAD 行重新 `register(JOINING, epoch 0, grpcPort())` → `markState(ACTIVE)`（epoch 重置，唯一合法 DEAD 复活路径）；由心跳自检与管理面 revive 调用 |
| `synchronized shutdown()` | 幂等：ACTIVE/SUSPECTED → `markState(LEAVING)`（异常仅 warn）→ 停采样线程 → 停心跳线程（shutdownNow + awaitTermination 5s）→ `grpcHost.stop()` → `tombstone(DEAD)`；start 失败后调用也安全 |
| `sampleOnce()`（私有，S13） | `monitor.snapshot()` 刷新 `latestSnapshot`；异常仅 warn 保留旧值 |
| `heartbeatOnce()`（私有） | 取 `latestSnapshot`（null 时现采）→ `registry.heartbeat(self, snapshot)`；**每 5 拍自检**：本节点在注册表已被判 DEAD（假死暂停后恢复）→ `reRegister()`；异常仅 warn 不中断循环 |

**线程模型**：两个单线程 daemon `ScheduledExecutorService`——`rt-sampler-{nodeId}`（`scheduleWithFixedDelay` 采样，与心跳解耦：心跳只读缓存快照，monitor 卡死不拖心跳）+ `rt-heartbeat-{nodeId}`（`scheduleAtFixedRate` 固定速率）。

正常生命周期状态序列：`JOINING(0) → ACTIVE(1) → LEAVING(2) → DEAD(3)`；误判复活序列：`DEAD(n) → JOINING(0) → ACTIVE(1)`。

### 3.7 ClusterSchema

- `static bootstrap(DataSource)`：classpath 读 `sql/rt_cluster.sql`（UTF-8）→ 去 `--` 行注释 → 按 `;` 拆分 → 在 `pg_advisory_lock(4001, 1)` 会话级锁内逐条执行（finally unlock）。
- advisory lock 目的：跨节点并发 bootstrap 串行化，规避 PG `CREATE TABLE IF NOT EXISTS` 的 pg_type 唯一键竞态（3 节点场景实测暴露）。

### 3.8 decommission 子包（节点退役记录存储）

退役的**推进逻辑**在 scheduler（`DecommissionDriver` 端口）与 server（`RuntimeDecommissionCoordinator`/`DecommissionService`），本包只存记录：

| 类 | 说明 |
|---|---|
| `DecommissionState`（enum） | `DRAINING, REMOVING, COMPLETED, FAILED`；`terminal()` = COMPLETED/FAILED；流程 DRAINING→REMOVING→COMPLETED，两阶段均可→FAILED（**存储层不校验跃迁**，由协调器保证） |
| `DecommissionRecord`（record） | `(NodeId node, DecommissionState state, boolean force, String detail, long startedAtMillis, long updatedAtMillis, Long completedAtMillis)`；completedAt 装箱 null=未完成；force=最后节点丢弃数据授权 |
| `DecommissionStore`（接口） | `get(node)` / `listActive()`（非终态）/ `upsert(record)` / `setState(node, state, detail)`（刷新 updated_at）；每节点一条记录（PK node_id），终态记录保留可查 |
| `InMemoryDecommissionStore` | CHM + Clock；`setState` 进入终态时写 completedAt（computeIfPresent，缺行 no-op） |
| `JdbcDecommissionStore` | `ON CONFLICT (node_id) DO UPDATE` 全列 upsert；**与内存版不对称：`setState` 不写 completed_at**（仅完整 upsert 能落完成时刻）；缺行静默 no-op |

## 5. 与其他模块的关系

- 依赖 common（领域类型）与 proto（pom 声明；gRPC 宿主 `GrpcServerHost` 来自 proto 模块）。
- membership 通过函数式接口与之协作（无编译依赖）：`PeerDirectory` ← `listAlive()`、`StateSink` ← `markState()`（含 S12 epoch 防护版）、`SuspicionSink` ← `NodeSuspicionStore.vote/recall`、`selfInfo` ← `get(self)`。
- scheduler 依赖 `NodeRegistry`（listAlive/get 解析节点地址）与 `NodeSuspicionStore`（多数仲裁计票）及退役端口 `DecommissionDriver`（记录读写经本包 `DecommissionStore`）；server 装配 `NodeRuntime`、`Jdbc/InMemoryDecommissionStore`、`Jdbc/InMemoryNodeSuspicionStore`。

## 6. 测试覆盖

| 测试类 | 覆盖点 |
|---|---|
| `NodeStateMachineTest` | 5×5 全矩阵合法/非法交叉验证；**DEAD 仅可到 JOINING**（其余目标全抛）；同态一律非法；null 拒绝 |
| `InMemoryNodeRegistryTest` | register upsert 重置、heartbeat 刷新保留状态、markState 跃迁+epoch、非法跃迁不污染 epoch、listAlive 过滤、tombstone 幂等、DEAD 后重新 register 可再次推进到 ACTIVE |
| `InMemoryNodeSuspicionStoreTest` | 同观察者重复投票覆盖不叠加；TTL 边界计票；按 suspect 分组；recall 仅撤本人票且幂等；clear 清全票；pruneExpired 只删过期行；未知 suspect 零票 |
| `OsResourceMonitorTest` | TestClock 时间戳精确匹配；cpuPercent ∈ [0,100]；used ≤ total；默认 SystemClock 非空 |
| `NodeRuntimeTest` | 随机端口注册实际端口；复用已启动 host；重复 start 抛异常；心跳循环在 monitor 故障后存活；shutdown 停心跳、LEAVING→DEAD、幂等；未 start 直接 shutdown 无副作用 |
| `NodeRuntimeStartFailureOrphanReproTest` | 端口占用致 start 抛 IOException → 行内 tombstone 为 DEAD（非残留 JOINING）+ 不在 listAlive；随后 shutdown 保持 DEAD |
| `Phase5ClusterTest` | S2 复活：高 epoch 的 DEAD 行 `reRegister()` → ACTIVE 且 stateEpoch 重置（< 死亡 epoch），重新进入 listAlive |

> `JdbcNodeRegistry`、`ClusterSchema`、`decommission` 子包**无独立单测**（PG 行为由 server 模块 Testcontainers 冒烟 IT 覆盖，见 [12-快速开始.md](12-快速开始.md) §7）。
