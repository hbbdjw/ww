# runtime-migration 模块

> 包路径：`com.ww.runtime.migration` ｜ 源码：`runtime/migration/src/main/java/com/ww/runtime/migration/`（14 个主类）
> 定位：**分区迁移——数据流传输与任务控制**：数据面搬运 + 切主/副本提升分流。
>
> **修订注记（2026-10-20，P0-1 修复）**：①**键型断点游标**——`PartitionDataAdapter` 新增 `exportChunks(..., cursor)` / `cursorOf(piece)` / `supportsCursorResume()`，`FetchReq` 增 `from_cursor`；Cache 游标 = `kind序号|Base64(key)`，Storage = `Base64Url(bucket + 0x00 + key)`；并发写入下位置断点不再错位；②**迁移期源分区冻结**——数据阶段前后 `FreezeGuard` 在源节点冻结该分区写入（TTL 默认 5 分钟、批间 30s 续期、任务结束立即解冻；执行节点崩溃由 TTL 自愈），经迁移 RPC `FreezePartition` + `CapabilityManager` 冻结钩子贯通；③**断点一律从零重放**——恢复的任务可能跨越未冻结窗口，位置/游标均不可信，幂等导入兜底（性能换正确性）；④`Meta` 增 `cursorB64` 字段；`handleChunk` 落进度不再写 null（保留 epoch/sourceCount/游标）。

## 1. 模块职责

- 驱动单个分区迁移任务走完 **10 态状态机**（PENDING→…→COMPLETED）；
- 完成源节点导出 → 目标节点导入 → 放置切主（cutover CAS）→ **源端分区清理**全流程；
- 支持**断点续跑**（checkpoint 持久化）、**SHA-256 checksum 校验**、**限流**、**重试与取消**；
- gRPC 传输：FetchPartition（服务端流）+ TransferStream（双向流，ack 重发）+ CountPartition/ClearPartition（源端计数/清理）；
- **跨节点路由**：RoutingPartitionAdapter 按任务 source/target 把数据面调用路由到「本地组合适配器 | 远端节点」——任何能力注册进 CompositePartitionAdapter 即自动获得跨节点迁移；
- 存储无关：`PartitionDataAdapter` SPI 隔离具体存储（Mock/Cache/Storage/Remote/Routing）。

**不依赖 scheduler 模块**：以 `migrateAndWait` 提供 scheduler 期望的语义，宿主层用 `RuntimeMigrationCoordinator` 对接。

## 3. 关键类详解

### 3.1 MigrationStateMachine（10 态状态机）

合法跃迁表（任何状态写入前必须经 `check` 校验）：

| from | 允许 to |
|---|---|
| PENDING | PREPARING, CANCELLED |
| PREPARING | SNAPSHOT, FAILED, CANCELLED |
| SNAPSHOT | COPYING, FAILED, CANCELLED |
| COPYING | SYNCING, FAILED, CANCELLED |
| SYNCING | CUTOVER, FAILED, CANCELLED |
| CUTOVER | VERIFYING, FAILED（**切主已生效，不可再取消**） |
| VERIFYING | COMPLETED, FAILED |
| COMPLETED | （终态，无出边） |
| FAILED | **PENDING（唯一终态出边：重试）** |
| CANCELLED | （终态，无出边） |

方法：`check(from,to)`（非法抛 `IllegalStateTransitionException`）、`canTransition`（不抛版）、`isTerminal`（COMPLETED/FAILED/CANCELLED）。

### 3.2 MigrationTask（record）

| 字段 | 说明 |
|---|---|
| taskId | BIGSERIAL 自增 |
| capability / partition | 能力 + 分区 |
| fromNode | 源节点（**可 null**：目标集新增分区无历史归属） |
| toNode | 目标节点 |
| state | MigrationTaskState |
| checkpointOffset / itemsDone | 断点偏移（条目数）/ 已完成条目 |
| checkpointJson | 断点元数据 `{"epoch":E,"sourceCount":S[,"cursorB64":"..."]}`（cursorB64 = 键型游标 Base64Url） |
| updatedAtMillis | 更新时间 |

派生：`withState(...)`、`withProgress(...)`（checkpointJson 传 null 保留原值）。

### 3.3 MigrationTaskStore（接口）与两实现

| 方法 | 语义 |
|---|---|
| `long create(capability, partition, from, to)` | 建任务（PENDING） |
| `get / listActive / listAll` | listActive = 非终态按 taskId 升序 |
| `boolean transition(taskId, newState)` | **状态机校验 + CAS 写**：`UPDATE ... WHERE task_id=? AND state=?`（WHERE 即 CAS，命中 0 行抛 MigrationException） |
| `saveProgress(taskId, offset, items, json)` | 持久化断点（不改状态）；json 传 null 保留原值 |

- 内存版：synchronized + `tasks.replace(id, current, updated)` CAS。
- JDBC 版：create 用 `INSERT ... RETURNING task_id`；saveProgress 用 `COALESCE(?, checkpoint_json)` 实现传 null 保留。

### 3.4 MigrationEngine（编排引擎，存储无关）

字段：store、adapter（PartitionDataAdapter）、placementStore、config、clock；常量 `MAX_IMPORT_ATTEMPTS=3`、`PROGRESS_PERSIST_BATCH=16`、`MAX_SYNC_ROUNDS=10_000`。

| 方法 | 行为 |
|---|---|
| `boolean migrateAndWait(capability, moves)` | 每 move `obtainTask`（**活动任务复用**，不重复建）→ `runAll`（**虚拟线程池** `newVirtualThreadPerTaskExecutor` + Semaphore 限并发）→ 全部 COMPLETED 返回 true，任一 FAILED 返回 false（其余跑完） |
| `void resumeAll()` | 启动恢复：listActive 按最新 checkpointOffset 续跑；再对 FAILED 任务**逐一复核当前状态**（多节点共享 DB 防并发重置噪声）后 `transition(FAILED→PENDING)` 续跑（断点保留） |
| `boolean cancel(taskId)` | 不存在抛 MigrationException；仅非终态可取消 |

**runTask 状态机驱动执行流程**（按当前状态跳入，对断点续跑友好；CAS 冲突=他人已推进 → TaskContended 静默放弃，不标 FAILED）：

```
PENDING → PREPARING : transition
PREPARING  : resolveEpoch —— 校验 placement 当前 owner == fromNode（from=null 仅读 epoch）
             返回该 epoch 作为 cutover 的 expectedEpoch；owner 不符抛 FencedException
PREPARING → SNAPSHOT
SNAPSHOT   : sourceCount = adapter.itemCount(cap, partition, fromNode)   ← 节点感知（源端计数）
             persistProgress 写 checkpoint_json {"epoch", "sourceCount"}
SNAPSHOT → COPYING
COPYING    : copyRemaining —— 自最新断点 exportChunks（Iterator 惰性流）
             逐片 importPieceWithRetry（checksum 引擎侧只算一次、随 importChunks 透传；重试 ≤3 次）
             每 16 片 saveProgress、异常前必落盘、finally closeExportChunks（T24 防 FD 泄漏）
             → throttle 限流睡眠
COPYING → SYNCING
SYNCING    : syncUntilQuiescent —— 反复增量拉取直至为空（防复制期间新写漏迁）
             最多 10_000 轮，不收敛抛 MigrationException
SYNCING → CUTOVER
CUTOVER    : cutOverOrPromote —— 以 store 最新 checkpoint epoch 为准：
             目标已持该分区 REPLICA 行 → placementStore.promoteReplica（数据已在，免搬运且防撞主键）
             否则 placementStore.cutover(cap, partition, toNode, epoch) ← CAS 切主（fencing）
             失败抛 FencedException（INFO 级标 FAILED，下轮重试）
CUTOVER → VERIFYING
VERIFYING  : targetCount = adapter.verifyCount(cap, partition, toNode)
             targetCount < sourceCount（sourceCount≥0 时）抛 MigrationException（对账失败）
VERIFYING → COMPLETED
COMPLETED  : clearSourcePartition —— 尽力清理源端分区（from=null 跳过）
             失败仅 WARN 不回滚任务终态；残留由启动清扫（retainPartitions/PartitionSweeper）兜底
```

**异常分类**（runTask catch）：TaskContended=DEBUG 静默（并发执行者已推进）；FencedException=INFO+FAILED（保留断点）；迟到重复执行者见终态=INFO 直接返回；`FAILED_PRECONDITION`（沿 cause 链识别，端点能力未启动/冻结的启动窗口）=INFO+FAILED 保留断点下轮重试；其余 RuntimeException=WARN 全堆栈+FAILED。

### 3.5 PartitionDataAdapter（SPI，存储防腐层）

**行格式**：`key + 0x01 + value + 0x02`（UTF-8），一个分片可含多条目。

| 方法 | 用途 |
|---|---|
| `itemCount(capability, partition)` | 本地分区计数 |
| `Iterator<byte[]> exportChunks(capability, partition, fromCheckpoint)` | 自断点导出（**惰性流**：跳过前 N 条，逐片产出——大分区不整载入堆；旧位置断点语义，Mock/旧实现沿用） |
| `Iterator<byte[]> exportChunks(capability, partition, fromCheckpoint, cursor)` | **键型游标导出（P0-1）**：游标非空时忽略位置断点，只导出 `> cursor` 的条目；`cursorOf(capability, piece)` 从完整条目分片提取游标（存储仅 fin 片）；`supportsCursorResume()` 声明能力 |
| `boolean freezePartition(capability, partition[, source], ttlMillis)` | **源分区停写冻结（P0-1）**：`ttlMillis<=0` 立即解冻；死源（不可解析）视为无需冻结 |
| `boolean importChunks(capability, partition, chunks)` | 幂等 upsert 导入 |
| `verifyCount(capability, partition)` | 本地对账计数 |
| `default closeExportChunks(iterator)` | T24：AutoCloseable 则 close（吞异常）——引擎 finally 调用防 FD 泄漏 |
| `itemCount/exportChunks/verifyCount` **带 source/target 重载**（default 委托本地） | 引擎跨节点迁移时调用，本地适配器零改动 |
| `importChunks(capability, partition, chunks, target, taskId)`（default） | 远端导入路由 |
| `importChunks(..., List<String> checksums)`（default） | 引擎调用点：透传预计算 SHA-256（大分片不重算） |
| `clearPartition(capability, partition, source)` | 迁移 COMPLETED 后清理源端分区（default 抛 MigrationException=未实现，引擎尽力调用） |
| `retainPartitions(capability, keep)` | 启动清扫：保留谓词通过的分区（default 0=未实现） |
| `compact(capability)` | 持久化压实（default no-op，如 Cache AOF 重写） |

**MockPartitionAdapter**：委托同一 `MockCapability` 实例（同进程源/目标直连）；export 按 key 字典序**一条目一分片**（断点跨重启确定性）；import 解析后走 `importPartition`（Map 语义幂等）；clearPartition 委托 `MockCapability.clearPartition`。

**RemotePartitionAdapter**：经 gRPC 远端访问（通道 maxInboundMessageSize=8MB，对齐 GrpcServerHost 约定）。
- 构造支持 `(channel, taskId)` 绑定任务后可经 TransferStream 写入（taskId=0 时 importChunks 不可用）；
- `exportChunks`：blocking stub `fetchPartition`（gzip 压缩，**FETCH_DEADLINE_SECONDS=1800**——惰性流覆盖整个拉取-导入循环），逐片 `ChunkCodec.verify`，不符抛 MigrationException；
- `importChunks`：分片入 pending → `sendRound`（async stub transferStream，单轮等 ack `ROUND_TIMEOUT_SECONDS=60`）→ 收集 ok=false 的 ack_seq 要求重发 → 最多 3 轮；checksum 优先用调用方预计算值；
- `itemCount/verifyCount`：经 `countPartition` RPC（`RPC_DEADLINE_SECONDS=30`，不再全量拉取计数）；
- `clearPartition`：经 `clearPartition` RPC（非 ok 时 WARN 打印接收端 reason）；
- 常量汇总：FETCH 1800s / ROUND 60s / RPC 30s / MAX_RESEND_ATTEMPTS 3 / 入站上限 8MB。

**RoutingPartitionAdapter**（跨节点迁移核心接线，能力无关；`record Endpoint(String host, int port)`）：按任务的 source/target 把数据面调用路由到「本地组合适配器 | 远端节点 RemotePartitionAdapter」（通道按节点缓存，maxInbound 8MB，`close()` 逐通道 shutdown + await 3s）。规则：
- source/target 为 null → 计数 0/空迭代器（引导型新分区空分区语义）；== self → 本地直连；
- **死源语义**：源节点无法解析（非 ACTIVE/未注册）→ WARN 后按空分区迁移（数据丢失窗口，与调度器治愈迁移同语义）；可解析但 RPC 失败 → 异常上抛，任务 FAILED 走冷却重试；
- 目标不可达 → MigrationException("import target unreachable")（任务 FAILED 重试，目标可能瞬时启动中）；
- 宿主装配：`RuntimeAssembly.routingPartitionAdapter`（resolver=NodeRegistry ACTIVE 节点 host:grpcPort），**MigrationEngine 注入本适配器**即获得跨节点能力；`MigrationServer` 注入的是本地组合适配器（CompositePartitionAdapter）。

### 3.6 MigrationServer（gRPC 服务端，继承 MigrationImplBase）

挂在数据持有节点上，六类 RPC（能力无关——capability 参数经组合适配器按能力分发）：

| RPC | 行为 |
|---|---|
| `fetchPartition`（服务端流） | 按 from_checkpoint 调 localAdapter.exportChunks 分片推送；每片带 seq/fin/checksum/累计 checkpointOffset；无数据发一个空 fin 片表达结束；**能力未就绪（未启动/冻结）回 `FAILED_PRECONDITION`（INFO）**，其余 onError(INTERNAL) |
| `transferStream`（双向流接收端） | onNext：查任务 → 终态拒绝（ack 带 reason "already terminal"）→ 首次加载进度 → checksum 校验（不符回 ok=false 要求重发）→ importChunks（失败回 ok=false "import failed, resend"）→ 累计进度 → fin 时 saveProgress 并回最终 ack |
| `countPartition`（unary） | localAdapter.itemCount（SNAPSHOT/VERIFYING 对账计数；能力未就绪回 FAILED_PRECONDITION） |
| `clearPartition`（unary） | localAdapter.clearPartition（迁移完成后释放源端；异常类名入 ack message） |
| `controlTask`（unary） | action 归一小写：cancel/cancelled 且非终态 → transition(CANCELLED)；终态/不支持返回 false |
| `reportProgress`（客户端流） | 逐条 saveProgress；完成回 ProgressSummary("accepted N reports") |

### 3.7 ChunkCodec（分片编解码 + checksum）

- 常量：`DEFAULT_CHUNK_SIZE = 4MB`；`SEP_KV=0x01`、`SEP_ENTRY=0x02`。
- `encode(taskId, pieces)`：seq 从 0 起、仅末片 fin=true、checkpointOffset 按累计**字节数**；
- `sha256Hex(data)`：SHA-256 小写 hex；
- `verify(data, checksum)`：大小写不敏感比对；
- `countEntries(piece)`：按 0x02 计数。

### 3.8 MigrationConfig（record）

| 参数 | 默认 | 含义 |
|---|---|---|
| maxConcurrentTasks | 2 | 最大并发迁移任务数（Semaphore） |
| maxBytesPerSecond | 64MB/s | 限流目标速率 |
| chunkSize | 4MB | 分片大小 |
| ackWindow | 8 | 在途未确认分片窗口 |

限流：`throttleMillisPerChunk = chunkSize × 1000 / maxBytesPerSecond`（默认 4MB/64MBps = 62ms/片）。

### 3.9 MigrationSchema

`bootstrap` 执行 `sql/rt_migration.sql`，advisory lock `pg_advisory_lock(4001, 5)` 串行化。

## 5. 幂等 / 重试 / 断点续跑机制汇总

| 层级 | 机制 |
|---|---|
| 任务级 | obtainTask 复用同 capability+partition+to 的活动任务 |
| 分片级 | importChunks upsert（幂等语义） |
| 单片重试 | importPieceWithRetry 最多 3 次（checksum 引擎侧预计算透传，不重算） |
| 远端重发 | 按 ack_seq 重发最多 3 轮 |
| 状态 CAS | `UPDATE WHERE state=?` 防并发修改；并发推进者 TaskContended 静默放弃 |
| 断点 | SNAPSHOT 写 checkpoint_json；COPYING 每 16 片 saveProgress（异常前/收尾必持久）；exportChunks 为 Iterator 惰性流 + 键型游标；**恢复任务一律从零重放**（跨越未冻结窗口时位置/游标不可信）；resumeAll 重启续跑 |

## 6. 与其他模块的关系

- 依赖 common/proto/placement/capability(Mock)；**不依赖 scheduler**；
- server 的 `RuntimeMigrationCoordinator` 把 `MigrationEngine.migrateAndWait` 适配为 scheduler 的 `MigrationCoordinator` 端口（engine 内部已调用 cutover，适配器直接委托）。
