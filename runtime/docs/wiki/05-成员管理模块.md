# runtime-membership 模块

> 包路径：`com.ww.runtime.membership` ｜ 源码：`runtime/membership/src/main/java/com/ww/runtime/membership/`（5 个主类）
> 定位：**成员关系——心跳与成员变更事件**：集群成员关系与故障检测。

## 1. 模块职责

- `MembershipService` 同时是 gRPC 服务端（`MembershipGrpc.MembershipImplBase`）与心跳客户端；
- 周期性双向流心跳与 peer 交换成员视图，采用 **gossip 悲观合并 + 直证例外**规则收敛视图；
- **视图版本化增量确认（S1②）**：请求带 `known_ack_version`，视图无实质变化时应答回空 members——全量视图带宽从每 tick O(N²) 降为变更期 O(N²)，故障检测时序不变；
- 基于 **Phi Accrual 自适应怀疑度**（暖窗期回退固定静默时长）判定 SUSPECTED/DEAD：φ≥3 疑似、连续 2 周期 φ≥8 判死，并回写宿主注册表（`StateSink`）；**DEAD 墓碑从目录消失超时后驱逐（S10）**，防视图单调增长；
- 通过进程内监听器与 gRPC Watch 流发布成员变更事件。

## 3. 关键类详解

### 3.1 MembershipConfig（record）

| 字段 | 默认 | 校验 | 衍生/用途 |
|---|---|---|---|
| `heartbeatIntervalMs` | 1000 | > 0 | — |
| `suspectAfterMisses` | 3 | >= 1 | `suspectTimeoutMs = suspect × interval`（默认 3000ms），**仅 φ 暖窗期回退** |
| `deadAfterMisses` | 6 | >= suspect | `deadTimeoutMs = dead × interval`（默认 6000ms），**仅 φ 暖窗期回退** |
| `phiSuspectThreshold` | 3.0 | 正有限 | φ≥阈值判 SUSPECTED（≈0.1% 误判概率） |
| `phiDeadThreshold` | 8.0 | finite 且 ≥ suspect | φ≥阈值进入死亡候选（Cassandra/Akka 同级） |
| `deadConfirmations` | 2 | >= 1 | φ 连续多少个检测周期超死阈值才升级 DEAD |
| `phiMaxSampleSize` | 200 | >= 1 | 心跳间隔环形样本窗口容量 |
| `phiMinSamples` | 3 | 1..maxSampleSize | 启用 φ 判定所需最少间隔样本（暖窗保护） |
| `phiMinStdDeviationMs` | 100 | > 0 | 间隔标准差下限，防稳态零方差令检测器过敏 |
| `phiAcceptablePauseMs` | 0 | >= 0 | 可接受暂停窗口（容忍 GC/调度停顿，窗口内静默不计怀疑度） |
| `localDeadWriteback` | true | — | 本地判 DEAD 是否直写注册表；仲裁模式置 false（DEAD 仅由 leader 多数票提升）。**2026-10-20 起 RuntimeProperties 默认仲裁开启，故装配默认 false**（`RUNTIME_SUSPICION_QUORUM_ENABLED=false` 可回退老语义） |

工厂：紧凑 `of(interval, suspectMisses, deadMisses)`（φ 参数取默认）/ 全参 `of(...)` / `defaults()`。

### 3.2 MemberEvent（record）

- 字段：`String type`、`NodeInfo node`；类型常量 `NODE_ACTIVE` / `NODE_SUSPECTED` / `NODE_DEAD` / `NODE_UPDATED`。

### 3.3 PeerDirectory（@FunctionalInterface）

`List<NodeInfo> peers()` —— 返回除自身外应心跳的存活节点。宿主侧适配 `NodeRegistry.listAlive()`。

### 3.4 StateSink（函数式接口，S12 扩展）

- `void apply(NodeId id, NodeState newState)`（抽象方法，兼容旧签名）；
- `default void apply(NodeId, NodeState, long observedEpoch, boolean directEvidence)`（默认委托两参版）——**防护契约**：宿主适配实现据 `observedEpoch` 拒绝旧 epoch 覆盖新状态；`directEvidence=true`（节点自报）豁免防护，为绝对权威；`observedEpoch<0` 表示无纪元信息。

### 3.4b SuspicionSink（接口，多级仲裁）

- `vote(suspect, phi)`：本地检测周期中 peer 处于 SUSPECTED/DEAD 时每周期刷新投票；
- `recall(suspect)`：SUSPECTED→ACTIVE 恢复（含 gossip/直证早于检测 tick）与 `stop()` 优雅退出时撤票；
- `SuspicionSink.NOOP`：未开启仲裁时零开销（传统本地直写 DEAD 语义）；
- 观察者身份由宿主适配填充（server 中 `vote(suspect, self, phi)` 桥接到 `NodeSuspicionStore`）。

**修订注记（2026-10-20）**：`NodeInfoP` 增 `zone` 字段（故障域随心跳 gossip 传播，P1-9）。

**仲裁模式语义（`localDeadWriteback=false`）**：本地视图仍标 SUSPECTED/DEAD 且 gossip 照常传播，但 `transitionLocal(DEAD)` 不回写 StateSink——注册表 DEAD 只能由调度器 leader 按 TTL 内多数观察者怀疑票提升；SUSPECTED 回写保留（供 LB 摘流与可见性）。

### 3.5 MembershipService（核心，gRPC 服务端 + 心跳客户端一体）

**常量**：`MAX_CONSECUTIVE_SEND_FAILURES = 3`（连续发送失败重建通道，规避 JVM DNS 负缓存卡死）；`EVICT_AFTER_DEAD_VANISHED_ROUNDS = 10`（S10 驱逐窗口 = 10×deadTimeoutMs）。

**字段**：
- 注入：`self`、`selfInfo: Supplier<NodeInfo>`、`directory`、`stateSink`、`host: GrpcServerHost`、`config`、`clock`；
- 可变状态（均并发容器）：`view`（含自身）、`lastHeard`、`detectors`（每 peer `PhiAccrualFailureDetector`，懒建）、`deadOverThresholdRounds`（连续超死阈值计数）、`channels`、`consecutiveSendFailures`、`vanishedDeadSince`（S10 计时）、`knownPeerVersions`（S1② 每 peer 已知应答版本）、`lastUpdatedEventAt`（NODE_UPDATED 节流）、`listeners`/`watchers`（COW 列表）；`viewLock` 串行化 merge/transitionLocal/evict；`viewVersion: AtomicLong`（仅实质变化 +1，纯资源波动不计）；`lastSelfRefreshAt`（S1① 限频窗）；
- 执行器：心跳 tick 线程 + 心跳派发池 + 事件分发线程。
- 包内可见接缝：`recordSignal(id, heardAt)`（入站/出站存活信号统一入口）、`detectFailures(now)`、`phiOf(id)`，供 TestClock 确定性测试与 φ 可观测。

**PhiAccrualFailureDetector（单 peer 检测器）**：定长环形窗口维护间隔 μ/σ；`heartbeat()`/`heartbeat(now)` 喂样本（非正间隔忽略不污染分布）、`isReady()` 暖窗判定、`phi()`/`phiAt(now)` 输出怀疑度；σ 取 max(实测σ, minStdDeviationMs)；正态 CDF 用 A&S 7.1.26 erf 近似（无外部依赖）；概率下截断 1e-300（φ 封顶约 300）。

**生命周期**：

| 方法 | 行为 |
|---|---|
| `start()`（synchronized） | 幂等；首次 `host.addService(this)`（**必须先于 host.start**）→ 创建心跳线程（`membership-heartbeat-{self}`，单线程 daemon）→ 事件分发线程（`membership-events-{self}`，单线程 daemon）→ **S1③ 派发池 `membership-dispatch-{self}`（2~4 线程、队列 512、CallerRunsPolicy、core 可超时）** → 失效 selfInfo 缓存并 `refreshSelf()` → `scheduleWithFixedDelay(heartbeatTick, 0, interval)` |
| `stop()`（synchronized） | 停心跳（shutdownNow + await 2s，A4 等在途 tick）→ 停派发池（先排空再关，杜绝关通道后重建）→ 关闭全部 PeerChannel 并清空 channels/failures/knownPeerVersions/vanishedDeadSince → 完成 watchers `onCompleted()` → 优雅停事件分发（2s）→ 清空 view/lastHeard/lastUpdatedEventAt |
| `view()` | `Map.copyOf(view)` 不可变快照 |
| `addListener(Consumer<MemberEvent>)` | 注册进程内监听器 |

**gRPC 服务端**：

| RPC | 行为 |
|---|---|
| `heartbeat`（双向流服务端侧） | `onNext(HeartbeatReq)`：解析对端自报 `reported` → `lastHeard.put` + `merge(reported, directFromSource=true)` → 回 `buildAck(req.known_ack_version)`：先读当前 `viewVersion` 写入 `ack_version`，**请求方已知版本 == 当前版本 → members 置空**（视图无新信息）；否则回全量视图 |
| `watch`（服务端流） | 加入 watchers；`ServerCallStreamObserver.setOnCancelHandler` 客户端取消时自动移除 |

**心跳客户端（heartbeatTick 每周期）**：

```
refreshSelf()（S1①：限频至每 interval 最多一次，避免 O(N²) 注册表点查）
→ directory.peers()（异常降级空表）
→ 遍历 peers（跳过 null/self）：sendHeartbeat(peer) 任务入派发池（S1③，tick 不随 peer 数线性阻塞）
   · channelFor(peer)：`channels.compute` 原子重建——host:port 未变复用、变了关闭重建并清其 knownPeerVersion
     （未 start 返回 null，S21 防停机竞态重建）
   · 双向流发 HeartbeatReq{self, known_ack_version=knownPeerVersions[peer] 或 -1} 后 onCompleted()
   · onNext(ack)：lastHeard 更新 + 发送失败计数清零 + 记录 ack_version；
     members 为空 → 跳过 merge；否则逐条 merge(member, 对端自身条目为直证)
   · onError：debug + resetConnectBackoff()；连续失败计数 +1，≥3 → 移除并关闭 channel、
     清 knownPeerVersion（强制下轮全量）
→ 关闭目录中已消失节点的 channel → detectFailures(now) → evictVanishedDead(activeIds, now)
整体捕获 RuntimeException 仅 warn（保证调度循环不中断）
```

**故障检测（detectFailures：Phi Accrual 主路径 + 固定超时暖窗回退）**：

- 每个 peer 一个 `PhiAccrualFailureDetector`：入站心跳与出站 ack 统一经 `recordSignal(id, heardAt)` 喂样本，检测器以定长环形窗口（`phiMaxSampleSize`，默认 200）维护心跳到达间隔的均值 μ/标准差 σ（σ 取实测值与 `phiMinStdDeviationMs` 的较大者）；
- 仅监控 `lastHeard` 有记录的节点（纯 gossip 得知、无本地直接信号的节点不判定）；
- **暖窗回退（`detectByFixedTimeout`）**：检测器有效间隔样本 < `phiMinSamples`（冷启动/重连）时沿用固定静默时长：`silence > suspectTimeoutMs` → SUSPECTED，`> deadTimeoutMs` → 同 tick 内先 SUSPECTED 后 DEAD（保证事件顺序）；
- **φ 主路径（`detectByPhi`）**：`φ(now) = -log10(1 - CDF_normal(((now-lastSeen-pause)-μ)/max(σ,minStdDev)))`：
  - `φ ≥ phiDeadThreshold`：首个超阈周期先置 SUSPECTED，连续计数 +1；连续达到 `deadConfirmations`（默认 2）个周期才 `transitionLocal(DEAD)`；
  - `phiSuspectThreshold ≤ φ < phiDeadThreshold`：非 SUSPECTED/DEAD → `transitionLocal(SUSPECTED)`；
  - `φ < phiSuspectThreshold`：连续计数清零，当前 SUSPECTED → `transitionLocal(ACTIVE)`（恢复）；
  - `phiAcceptablePauseMs` 窗口内的静默从静默时长中扣除（Akka acceptable-heartbeat-pause 语义）；
- **本地 DEAD 永不判恢复**（复活只能经直证自报或重新注册）；
- `transitionLocal` **不提升 epoch**，经四参 `stateSink.apply(id, state, epoch, false)` 回写；
- 检测器状态（`detectors`/`deadOverThresholdRounds`）随 S10 驱逐与 `stop()` 同步清理；`phiOf(id)` 暴露当前怀疑度供可观测。

**DEAD 墓碑驱逐（S10，evictVanishedDead）**：

- 条件：非 self ∧ 不在目录（`listAlive`）∧ 视图状态 DEAD——从首见起 `vanishedDeadSince` 连续计时，回归目录或状态复活即重置；
- 静默超过 `10 × deadTimeoutMs` → 从 view/lastHeard/各计数表中彻底移除（防退役/缩容节点墓碑无限增长）。

**视图合并规则（gossip 悲观 + 直证例外）——`accept(local, incoming, directFromSource)`**：

| 场景 | 是否采纳 incoming |
|---|---|
| 直证（源节点自报，`directFromSource=true`） | **一律采纳**（不比 epoch——防重启节点被陈旧高 epoch DEAD 压制） |
| gossip：incoming epoch 更高 | 采纳 |
| gossip：incoming epoch 更低 | 拒绝 |
| gossip：同 epoch | 仅当 `pessimism(incoming) > pessimism(local)` 采纳（更悲观胜出） |

`pessimism`：ACTIVE=0，DEAD=2，其余（SUSPECTED/LEAVING/JOINING）=1。

其他细节：
- incoming.id == self 直接忽略（自身信息以本地为准）；
- 仅**实质变化**（新节点/状态跃迁/host/port/weight/stateEpoch）才 bump `viewVersion` 并触发事件；纯资源波动只更新条目不发事件不升版本；
- `NODE_UPDATED` 事件按节点节流：每 `suspectTimeoutMs` 窗口最多一次（状态变化事件重置节流窗）；
- merge 发现节点恢复为 ACTIVE 且本地非 ACTIVE **且本地非 DEAD** 时，锁外回写 `stateSink`（DEAD 不回写——防心跳恢复误"复活"已被注册表权威判死的节点）；
- 事件经 `eventDispatcher` 单线程串行投递：监听器异常互不影响；watcher 取消/出错收集后**循环外统一 removeAll**（CopyOnWriteArrayList 迭代器不支持 remove 的回归防护）。

**线程模型**：tick 单线程（fixed-delay，只入队）+ 派发池（2~4 线程并行发送）+ 事件分发单线程；view/lastHeard/channels 并发容器 + viewLock 串行化读-改-写。

## 4. 心跳机制小结

| 参数 | 默认 | 说明 |
|---|---|---|
| 心跳周期 | 1000ms | `scheduleWithFixedDelay` |
| SUSPECTED 判定 | φ ≥ 3.0（暖窗期：3 次未闻/3000ms） | 自适应历史间隔分布，GC/抖动不再固定一刀切 |
| DEAD 判定 | 连续 2 周期 φ ≥ 8.0（暖窗期：6 次未闻/6000ms） | 连续确认防瞬时抖动一击判死 |
| 间隔窗口 / 最小样本 | 200 / 3 | 滚动窗口估计 μ、σ；样本不足走暖窗回退 |
| σ 下限 / 可接受暂停 | 100ms / 0ms | 零方差兜底；可配 GC 宽限 |
| DEAD 墓碑驱逐 | 从目录消失且 DEAD 持续 10×deadTimeout（默认 60s） | S10，视图彻底移除 |
| 通道重建 | 连续发送失败 3 次 | 清已知版本强制全量 |
| 恢复 | 重新收到消息且 φ 回落 | SUSPECTED → ACTIVE（transitionLocal，epoch 不变）；DEAD 仅直证/重注册复活 |

## 5. 与其他模块的关系

- 依赖 common + proto；不依赖 cluster（通过 `PeerDirectory`/`StateSink`/`SuspicionSink`/`Supplier<NodeInfo>` 函数式接口在宿主层桥接）。
- server 装配时：PeerDirectory = `registry.listAlive()` 排除 self；StateSink = `registry.markState`（含 S12 epoch 防护与 NODE_DEAD 事件驱逐命令通道）；SuspicionSink = `NodeSuspicionStore.vote/recall`（观察者=self）；selfInfo 优先注册表当前视图、未注册用本地信息兜底。
