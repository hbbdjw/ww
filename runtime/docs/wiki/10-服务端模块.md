# 10. runtime-server — Spring 装配与节点进程

> 模块路径：`runtime/server`｜ artifactId：`runtime-server` ｜ 27 个主类
> 定位：**薄 Spring Boot 宿主（组装层）**。全部核心模块（cluster / membership / capability / placement / scheduler / migration / data / log）均为 Spring-free POJO，由本模块以构造注入方式组装为 Bean；它是 runtime 家族中**唯一允许依赖 Spring** 的模块。

## 1. 模块职责

- 提供节点进程入口（`RuntimeServerApplication`）与配置绑定（`RuntimeProperties`，前缀 `runtime.*`）。
- **装配**：`RuntimeAssembly`（唯一的宿主 `@Configuration`）把所有核心类构造注入组装为 Spring Bean，包括 jdbc/memory 双持久化模式切换与 CACHE/STORAGE 数据面全套组件。
- **编排**：`RuntimeBootstrapper`（`SmartLifecycle`，phase=`MAX_VALUE`）统一定义启动/停机顺序。
- **端口适配**：`PlacementViewAdapter`、`RuntimeMigrationCoordinator`、`RuntimeDecommissionCoordinator`、两个 PeerDirectory 适配等。
- **HTTP 管理面**：`/rt/*`（状态/期望态/退役/调度/日志）+ `/cache/*`、`/storage/*` 数据网关。
- **日志链路宿主侧**：`log` 包——批量落库、历史查询、SSE 实时流、跨节点 gRPC 聚合。

包结构：

```
com.ww.runtime.server

 ├── RuntimeProperties             # 配置 record（构造绑定 + 校验）
 ├── config/
```

## 2. RuntimeServerApplication（入口）

```java
@SpringBootApplication(scanBasePackages = "com.ww.runtime.server")
@ConfigurationPropertiesScan("com.ww.runtime.server")
public class RuntimeServerApplication {
    public static void main(String[] args) {
        SpringApplication.run(RuntimeServerApplication.class, args);
    }
}
```

- 扫描范围**仅限** `com.ww.runtime.server`——核心模块包不会被组件扫描，只能经 `RuntimeAssembly` 显式装配，保证核心模块零 Spring 依赖。
- 配置覆盖优先级：**环境变量（relaxed binding，`RUNTIME_NODE_ID` → `runtime.node.id`）> `application.yml` > `RuntimeProperties` 的 `@DefaultValue`**。

## 4. RuntimeAssembly（Bean 装配）

唯一的宿主 `@Configuration`。**Bean 只负责「构造」**；带顺序的启动/停机编排归 `RuntimeBootstrapper`。

### 4.1 持久化双模式（`runtime.store`）

| 模式 | 激活条件 | 仓库实现 | DDL |
|---|---|---|---|
| `jdbc`（默认） | `@ConditionalOnProperty(matchIfMissing=true)` | `JdbcNodeRegistry` / `JdbcCapabilityStateStore` / `JdbcPlacementStore` / `JdbcLeaseStore` / `JdbcMigrationTaskStore` / `JdbcDecommissionStore` | 启动时 6 个 `Schema.bootstrap`（含 LogSchema） |
| `memory` | `runtime.store=memory` | 对应 `InMemory*` 实现（含 InMemoryDecommissionStore） | 不建 DataSource、不执行 DDL |

DataSource 由 `spring-boot-starter-jdbc` 自动装配（HikariCP），连接 `spring.datasource.*`。

### 4.2 关键装配决策

- **gRPC 工作线程池（S19）**：`grpcServerExecutor` Bean = `ThreadPoolExecutor(core 8, max 64, 队列 1024, 线程名 grpc-server-worker, daemon, allowCoreThreadTimeOut)`，经 `setExecutor` 注入 `GrpcServerHost`——控制面+数据面共用宿主，杜绝 gRPC 默认无界 cached 池。
- **MembershipService 端口适配**：`PeerDirectory` = `registry.listAlive()` 排除 self；`StateSink` 匿名实现（S12 纪元防护 + 同态幂等）；`selfInfo` 优先注册表当前视图；NODE_DEAD 事件顺带 `grpcCommandChannel.evictNode()`（A3）。
- **迁移双适配器接线**：`CompositePartitionAdapter`（Map: MOCK→Mock、CACHE→Cache、STORAGE→Storage）挂 `MigrationServer`（本地接收端）；`RoutingPartitionAdapter(composite, self, resolver)` 挂 `MigrationEngine`（执行端，resolver=NodeRegistry ACTIVE 节点 host:grpcPort）。
- **PeerDirectory（能力侧）**：`CachePeerDirectory`/`StoragePeerDirectory` 用 NodeRegistry+CapabilityStateStore 适配；`servingPeers()` = 该能力 actual=ACTIVE ∩ 存活——能力停用节点不参与 fan-out/复制。
- **MockCapability 的分区函数**：`key -> Partitioner.partition(key, partitionCount)`；STORAGE 口径 `bucket + "/" + key`。
- **StorageReplicator**：`setWriteHook` 挂到 StorageCapability + `setBucketReconciler(gateway::reconcileBuckets)`（T21 桶对账随复制对账跑）。

## 5. 端口适配类与协作组件

| 类 | 桥接 | 说明 |
|---|---|---|
| `PlacementViewAdapter` | capability `PlacementView` → `PlacementStore` | `owner()` 透传属主+epoch；`holders()` 返回 [PRIMARY, REPLICA…]（写后复制选点）；行缺失返回 empty |
| `RuntimeMigrationCoordinator` | scheduler `MigrationCoordinator` → `MigrationEngine.migrateAndWait` | 失败透传 false（engine 内部置 FAILED），调度器下周期重算重试 |
| `RuntimeDecommissionCoordinator` | scheduler `DecommissionDriver` → `DecommissionStore` 状态机 | Leader 每周期 `advance()`：DRAINING 门控（actual 全停 + PRIMARY 引用清零 + 副本重派，单轮 ≤256 分区）→ REMOVING（markState LEAVING→tombstone→能力记录删除→COMPLETED）；任一违规→FAILED |
| `DecommissionService` | REST → 退役记录 | `precheck`（只读：能力/数据量/PRIMARY 持有/是否需 force）；`start(node, force)` 幂等（非终态记录直接返回）；**force 语义**：能力最后 ACTIVE 主持有者且持 PRIMARY 时缺 force → 409 拒；通过后写 DRAINING 记录并把该节点全部 desired=ACTIVE 置 DISABLED；`progress` 查询 |
| `ClusterControlServer` | gRPC `ClusterControl` → `CapabilityManager` | start/stop 走 **convergeStart/convergeStop**（幂等）；nodeId≠self 拒绝；一切异常回 Ack(ok=false) |
| `HealthServer` | gRPC `Health` → `ReconcileLoop.isLeader` | 进程存活即 `healthy=true`，detail 带节点 id 与 leader 状态 |
| `PartitionSweeper`（cache 包，能力无关） | 启动清扫 | Bootstrapper 第 6.5 步执行：keep(p) = self 是 PRIMARY ∨ 有活动/FAILED 任务涉及 self；命中清理 `retainPartitions` 后 `compact`；放置表空一律不删（fail-safe） |

## 6. RuntimeBootstrapper（启动/停机编排）

`SmartLifecycle`，`getPhase()=Integer.MAX_VALUE`：**Web 服务器就绪后最后启动、停机时最先执行**。启动序列任一步失败即抛异常终止容器启动（Fail-Fast）。

### 6.1 启动序列（顺序不可交换）

```
(1) bootstrapStore     memory 跳过；jdbc：PG SELECT 1 可达性检查
                       + 6 个 Schema bootstrap（cluster/capability/placement/scheduler/migration/log，幂等）
(2) host.addService    MigrationServer → ClusterControlServer → HealthServer
                       → LogStreamGrpcServer → StorageGrpcServer → CacheGrpcServer
                       —— 必须在 host.start 之前（GrpcServerHost 启动后拒绝注册）
(3) membership.start   其内部 addService 自身并启动心跳；必须先于 nodeRuntime.start
(4) nodeRuntime.start  注册 JOINING → 绑端口（支持随机）→ ACTIVE → 采样+心跳线程；
                       失败连带停 membership 后抛异常
(5) 能力注册与引导     各能力 *-desired=true → setInitialDesired（首启写、已有记录不覆盖）
                       → capabilityManager.register(MOCK/CACHE/STORAGE)
                       → storageCapability.setWriteHook(storageReplicator)
                       → storageReplicator.start()
(5.5) 本地自收敛       遍历已注册模块：desired=ACTIVE 且 actual=DISABLED → convergeStart
(5.8) 成员收敛等待     awaitMembershipConvergence()（≤3s、500ms 轮询、ACTIVE 数连续 2 次稳定即返回）
(6) reconcileLoop      先手动 runOnce()（确定性首查：抢租约 + 首轮收敛）→ start() 守护循环
(6.5) partitionSweeper sweepAll()（放置/在途任务可见后、续跑前）
(7) migration.resumeAll()  断点续跑上次未完成的迁移任务
```

### 6.2 停机序列（倒序，全部幂等）

```
reconcileLoop.stop → storageReplicator.stop → storageGrpcServer.close → storageGrpcClient.close
→ cacheGrpcServer.close → cacheGrpcClient.close → routingPartitionAdapter.close
→ membership.stop → grpcCommandChannel.close
→ nodeRuntime.shutdown（LEAVING → 停采样/心跳 → host.stop → tombstone DEAD）
```

日志批量线程由 `RuntimeLogBatchWriter.@PreDestroy` 独立收尾（drain 残余）；退役无独立线程（随 ReconcileLoop 停止）。

## 7. HTTP 端点总表

### 7.1 RuntimeAdminController（`/rt`，管理面）

**§60 约束：管理面只写期望态（desired），不提供直接修改 actual 的端点**（revive 例外——它重置的是注册表行，非能力 actual）。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/rt/status` | 集群快照：leader/leaseOwner/capabilities/primariesByCapability/placementsByCapability/self/members/活动迁移数/退役记录 |
| GET | `/rt/status/stream` | **SSE**：每 1s 推 status 事件，30s keep-alive 帧（StatusStreamService） |
| GET | `/rt/nodes` | 全量节点视图（含 DEAD 墓碑） |
| PUT | `/rt/nodes/{id}/capabilities/{type}/desired` | 写期望态 `{"desired":"ACTIVE"|"DISABLED"}`；非法/最后节点保护 → 400 |
| POST | `/rt/nodes/{id}/revive` | 误判 DEAD 复活：本节点 → `reRegister()`；远端 → 仅重置回 JOINING（绝不代写远端 ACTIVE）；非 DEAD → skipped |
| GET | `/rt/placement/{capability}/lookup?key=` | key → partition/ownerNode/epoch/host/grpcPort 解析（无属主 404） |

### 7.2 退役（RuntimeDecommissionController，`/rt`）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/rt/nodes/{id}/decommission/precheck` | 只读预检：能力/数据量/PRIMARY 持有/是否需 force/降级警告 |
| POST | `/rt/nodes/{id}/decommission` | 发起（body `{"force":bool}` 可空）；非终态 202、终态 200；违规 409 |
| GET | `/rt/nodes/{id}/decommission/status` | 进度（记录 + 各能力剩余 PRIMARY 估计） |

### 7.3 调度观测（RuntimeScheduleController，`/rt`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/rt/migration/tasks?capability=&scope=active|all&limit=100` | 任务列表（taskId 降序，上限 500）→ `{total,truncated,tasks}` |
| POST | `/rt/migration/tasks/{id}/cancel` | 取消（非终态）；不存在 404 |
| POST | `/rt/migration/resume` | FAILED→PENDING 断点续跑触发 |
| POST | `/rt/scheduler/rebalance` | body `{"capability":...}` 重置冷却立即重平衡（leader 亲和，非 leader 返回 leader 指向） |
| GET | `/rt/placement/{capability}/distribution` | 各节点 primaries/replicas 分布 |
| GET | `/rt/cache/node-stats` | 各节点 CACHE actual/keyCount/reachable（peer 走 countKeysStrict） |
| GET | `/rt/storage/node-stats` | 各节点 STORAGE actual/objectCount/reachable（peer 走 countObjectsStrict） |

### 7.4 日志（RuntimeLogQueryController / RuntimeLogStreamController）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/rt/logs?level=&node=&keyword=&page=&size=` | 历史分页（offset 模式，size 上限 500）→ `{total,page,size,logs}` |
| GET | `/rt/logs?beforeTs=&beforeId=` | 历史翻页（keyset cursor 模式）→ `{logs,hasMore}` |
| DELETE | `/rt/logs?fromTs=&toTs=` | 按时间范围清理 |
| GET | `/rt/log/stream?level=&node=&keyword=` | **SSE 实时流**（`text/event-stream`）；hub 模式聚合本节点 LogBus + 对端 `LogStream.Stream` gRPC（只推本地不递归、断线 3s 重连） |

### 7.5 CacheDataController（`/cache`，CACHE 数据网关）

经 `CacheGateway` 按 placement 路由（本地属主直连，否则 gRPC 转发，StaleEpoch 重查属主重试一次）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/cache/keys?prefix=&limit=200` | 集群 key 列举（fan-out 合并去重取 TTL 较小者，上限 10000） |
| DELETE | `/cache/keys?prefix=` | 前缀子树批量删除（并行逐 key 路由）→ `{deleted,failed}` |
| GET | `/cache/{key}` | 读值（Map/List→json，余→text）；404 不存在 |
| PUT | `/cache/{key}?ttl=0&type=text|json` | 写值（ttl>0 相对过期毫秒；空 body/坏 json 400） |
| PUT | `/cache/{key}?nx=true&ttl=0&type=text|json` | 仅当 key 不存在时写入（原子 NX）；成功 `{applied:true}`，已存在 409 `{applied:false}` |
| DELETE | `/cache/{key}` | 删除（幂等，始终 204；不存在/已过期同样成功） |

错误映射：409（NX 已存在 / stale-epoch / not-owner）/ 423（frozen）/ 503（框架异常/转发失败）。

### 7.6 StorageRestController（`/storage`，S3 网关）

经 `StorageGateway` 路由；**任意节点可接收任意请求**，客户端无需感知拓扑（admin 侧自管存储端点已彻底下线）。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/storage?stats=` | 列桶（桶集经 SyncBucket 广播在各节点收敛）；`stats=true` fan-out 聚合 objectCount/totalSize |
| PUT | `/storage/{bucket}` | 建桶（幂等；本地落盘 + 广播） |
| DELETE | `/storage/{bucket}?recursive=` | 删桶（**远端先行**：集群级空判定，各 peer 全成功才删本地；非空默认 409） |
| GET | `/storage/{bucket}?prefix=&marker=&maxKeys=` | 列举（fan-out 全 servingPeers 单页合并，同 key 取最高 version，属主结果剔除 stale 复活，排序截断） |
| PUT | `/storage/{bucket}/{key...}` | 上传（流式分块；`Content-Type` 与 `x-amz-meta-*` 入元数据；属主 fencing） |
| GET | `/storage/{bucket}/{key...}` | 下载（全流式；单段 Range `bytes=start-`/`bytes=-N` → 206/416） |
| HEAD | `/storage/{bucket}/{key...}` | 元信息（x-amz-meta-* 回带） |
| DELETE | `/storage/{bucket}/{key...}` | 删除（属主落墓碑，副本经复制器异步删除） |

错误映射：409（fencing/非空桶/远端未确认）/ 423（frozen）/ 503 / 404。
节点间数据面（storage.proto）与写路径「主落盘 → 应答 → 异步复制（backlog + 周期对账）」详见 [13-数据面模块.md](13-数据面模块.md)。

### 7.7 CORS 与静态资源

`CorsConfig`：`/**` 全放通（allowedOriginPatterns `*`，GET/PUT/POST/DELETE/OPTIONS，maxAge 3600），异步超时 1 小时；`WebConfig`：`/` forward `/index.html`（runtime-ui 构建产物注入 `server/src/main/resources/static`）。

## 8. 日志链路宿主侧（server/log 包）

runtime-log 模块（见 [14-日志模块.md](14-日志模块.md)）止于 `LogBuffer`/`LogBus`；落库与暴露面全部在本包：

| 类 | 职责 |
|---|---|
| `JdbcLogStore` | `rt_log` 批量写 + offset/keyset 双分页查询 + 时间范围删除（plain SQL，非 Bean，按需构造） |
| `LogSchema` | `sql/rt_log.sql` 幂等建表；advisory lock `pg_advisory_lock(4001, 6)` |
| `RuntimeLogBatchWriter`（@Service） | 守护线程 `log-batch-writer`：`LogBuffer.pollBatch(batchSize, flushIntervalMs)` → jdbc+enabled 时 `batchInsert`（落库期 `setSuppressed(true)` 防自引用）→ `logBus.publish`；@PreDestroy drain 收尾 |
| `RuntimeLogStreamService` | LogBus → SseEmitter（30s 心跳、断连自动退订） |
| `RuntimeLogStreamHub` | 聚合订阅：本节点 + 对端 gRPC Stream 转发（虚拟线程 io 池） |
| `LogStreamGrpcServer` | logstream.proto 服务端——只推本节点、不递归 |
| `RuntimeLogQueryController` / `RuntimeLogStreamController` | 端点见 §7.4 |

## 10. 设计要点

1. **核心 Spring-free**：`RuntimeAssembly` 是核心类接触 Spring 的唯一边界；未来脱离 Spring 独立运行只需重写这一个装配类 + Bootstrapper。
2. **顺序约束显式化**：gRPC「注册先于启动」「membership 先于 nodeRuntime」「sweeper 在放置引导后、resumeAll 前」等全部集中在 `RuntimeBootstrapper`，Bean 之间无隐式启动顺序依赖。
3. **Fail-Fast 启动**：PG 不可达、DDL 失败、端口绑定失败等任一异常直接终止容器启动。
4. **依赖倒置**：模块间耦合点全部收敛为小适配类，核心模块互不知晓对方实现。
5. **管理/数据端点分离**：`/rt`（只写 desired + 观测）、`/cache`、`/storage`（数据面经网关路由），退役/调度操作也走 `/rt` 但全部是"意图"而非直接状态改写。
