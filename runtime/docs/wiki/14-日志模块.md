# runtime-log 模块

> 包路径：`com.ww.runtime.log` ｜ 源码：`runtime/log/src/main/java/com/ww/runtime/log/`（4 个主类）
> 定位：**日志采集总线（Spring-free）**——logback 事件 → 有界缓冲 → 进程内发布总线。落库（`rt_log`）、历史查询、SSE 实时流、跨节点 gRPC 聚合全部在宿主 runtime-server（见 [10-服务端模块.md](10-服务端模块.md) §8）。

## 1. 模块职责与数据流

```
logback 事件（业务线程）
   │ append()——零 IO：转换 LogRecord + 截断后入队
   ▼
DbLogAppender ──► LogBuffer（LinkedBlockingQueue，满即丢 + droppedCount 计数）
                     │ 宿主守护线程 pollBatch(batchSize, flushIntervalMs)
                     ▼
             server/RuntimeLogBatchWriter
                     ├─► JdbcLogStore.batchInsert → rt_log（落库期 setSuppressed 防自引用）
                     └─► LogBus.publish → 订阅者（SSE / 本节点 gRPC 流 / hub 聚合）
```

## 2. Maven 坐标与依赖

- 坐标：`com.ww:runtime-log:1.0-SNAPSHOT`
- 依赖：`runtime-common`、`slf4j-api`、`ch.qos.logback:logback-classic`（Boot BOM 版本，与宿主一致）；
- **零 Spring**（enforcer 门禁同核心模块；主源码唯一非 JDK import 为 logback/slf4j）；
- 宿主以 `logback-spring.xml` 声明 `<appender name="DB" class="com.ww.runtime.log.DbLogAppender"/>` 挂根 logger（logback 实例化，非 Spring 管理）。

## 3. 关键类

| 类 | 职责与要点 |
|---|---|
| `LogRecord`（record） | `(Long id, level, loggerName, threadName, message, stackTrace, node, timestamp)`——id 仅查询结果携带；timestamp 为事件真实产生时刻 |
| `DbLogAppender`（extends `AppenderBase<ILoggingEvent>`） | 转换 + 截断：message 8192 / logger 255 / thread 128 / stack 16384；静态 `setNodeKey(nodeId)` 由宿主注入。**防死循环两件套**：ThreadLocal `SUPPRESSED`（落库线程批量写期间不再采集）+ 线程名前缀排除（`log-batch-writer`、`log-sse-heartbeat`）；采集异常仅 addError 不外抛 |
| `LogBuffer`（进程内静态单例） | 队列默认容量 10000；`configure(capacity)` 启动重建并迁移旧队列（超出丢弃）；`offer` 满即丢 + `droppedCount()`；`pollBatch(max, timeoutMs)` 首条限时等待 + drainTo 凑批 |
| `LogBus`（实例，宿主装配为 Bean） | 订阅/广播：`subscribe(level, node, keyword, sink, onClose)`；过滤语义——level 忽略大小写精确、node 精确、keyword 小写后匹配 message/loggerName/node/stackTrace 四字段任一（空串=不过滤）；sink 抛异常自动移除订阅；`CopyOnWriteArrayList` 订阅表 |

## 4. 宿主侧配置键（runtime.log.*，server 模块消费）

| 键 | 默认 | 说明 |
|---|---|---|
| `runtime.log.enabled` | true | 落库开关（false/memory 模式仍消费队列防积压，仅跳过写库） |
| `runtime.log.batch-size` | 200 | 单批条数 |
| `runtime.log.flush-interval-ms` | 1000 | pollBatch 等待上限 |
| `runtime.log.queue-capacity` | 10000 | LogBuffer 容量 |

## 5. 与其他模块的关系

- 依赖仅 common；不依赖 proto/server——gRPC `LogStreamGrpcServer` 与 SSE 端点都在 server（本模块只到 LogBus 为止）；
- server 的 `RuntimeLogStreamHub` 用本模块 LogBus + proto `logstream.proto` 做跨节点聚合（对端只推本节点、不递归，天然无环）。

## 6. 测试覆盖（3 类 18 用例）

| 测试类 | 覆盖点 |
|---|---|
| `DbLogAppenderTest` | 正常采集含 nodeKey；SUPPRESSED 丢弃；排除线程名前缀；长消息截断；堆栈捕获；nodeKey 默认 unknown |
| `LogBufferTest` | offer/pollBatch 往返；超时空；满丢弃计数；configure 迁移旧队列；非法容量回退默认 |
| `LogBusTest` | 广播匹配；level 大小写；node 精确；keyword 四字段；unsubscribe 触发 onClose；异常 sink 自动移除；stop 全清 |

端到端链路（含 rt_log 建表/批量写/分页）由 server 模块 `RuntimeLogSmokeIT`（Testcontainers PG）覆盖。
