# runtime-scheduler 模块

> 包路径：`com.ww.runtime.scheduler` ｜ 源码：`runtime/scheduler/src/main/java/com/ww/runtime/scheduler/`（14 个主类）
> 定位：**调度器——控制面收敛器（Desired → Actual）**：Leader 租约 + 六阶段调谐 + 命令通道 + 退役驱动端口。
>
> **修订注记（2026-10-20）**：①`rt_scheduler_lease` 增 `leader_epoch`（换主单调递增，P1-2 fencing token），`acquireOrRenewWithEpoch/isCurrent` 配套；`runOnce` 及各副作用阶段（replaceAll/reassignReplicasBatch/setActual/tombstone/markState/decommission）执行前复核纪元；②`suspicionQuorumEnabled` **默认改为 true**（本地 φ 只投票，leader 多数票唯一提升 DEAD）；③排空/缩容的 `freeze(true)` 前经 CapabilityManager 冻结钩子先排空 STORAGE 复制 backlog（P1-3），副本提升不再基于落后副本；④迁移引擎在数据阶段自行冻结源分区（迁移日志见 09-迁移模块.md），重平衡路径不再依赖中心 freeze。

## 1. 模块职责

- **Leader 选举**：基于 `rt_scheduler_lease` 单行表的乐观锁租约，全集群至多一个 ReconcileLoop 以 Leader 身份执行（无固定 Master）；
- **调谐收敛（Reconcile）**：每周期对比 desired/actual，生成 START/STOP/FREEZE 命令 + 迁移/提升计划，幂等推进（含冻结补偿、JOINING 孤儿清扫、副本补足、治愈宽限期）；
- **期望态写入校验**（`DesiredStateWriter`）：拦截管理面非法写入（如清空最后一个服务节点），并提供首启引导语义 `setInitialDesired`；
- **命令下发**：本地直连 + gRPC 远程两种通道，统一返回布尔（失败不抛异常，下周期重试）；
- **退役驱动端口**（`DecommissionDriver`）：Leader 每周期末尾 `advance()`，实现由宿主注入（server 的 RuntimeDecommissionCoordinator）。

**不直接搬数据**：分区搬迁 + 切主经 `MigrationCoordinator` 端口委托给 migration 模块（编译期不依赖 migration）。

## 2. Maven 坐标与依赖

- 坐标：`com.ww:runtime-scheduler:1.0-SNAPSHOT`
- 依赖：`runtime-common`、`runtime-proto`（ClusterControlGrpc）、`runtime-cluster`（NodeRegistry）、`runtime-capability`（CapabilityStateStore/CapabilityManager）、`runtime-placement`（PlacementStore/Engine/Planner）、slf4j-api。

## 3. 关键类详解

### 3.1 LeaseStore（接口）与两个实现

| 方法 | 语义 |
|---|---|
| `boolean acquireOrRenew(String owner, long ttlMillis)` | 租约无主或已过期（`expiresAt < now`，恰等于视为仍持有）→ 抢占；自己是 owner → 续约；他人持有未过期 → false |
| `long acquireOrRenewWithEpoch(String owner, long ttlMillis)`（default，**P1-2**） | 同语义并返回单调 `leader_epoch`：换主（属主变更/过期被接管）+1，同属主续约不变；未获得返回 -1 |
| `boolean isCurrent(String owner, long epoch)`（default，**P1-2**） | 校验 (owner, epoch) 仍是当前有效 leader；JDBC 实现连 `expires_at_ms >= 数据库 NOW()` 一并校验，读取失败按非 leader 处理 |
| `Optional<String> currentOwner()` | 有效租约 owner（`expires_at_ms >= now`）；无/过期返回 empty |

无显式 release——租约靠过期自然释放（Leader 宕机后最迟 TTL 内被接管）。owner null/blank、ttl <= 0 抛 IAE。

- **InMemoryLeaseStore**：单锁保护 owner/expiresAt；过期语义与 JDBC 版对齐。
- **JdbcLeaseStore**：单行表 `rt_scheduler_lease`（id 恒 1）。**S20 顺序**：先条件 UPDATE（常规续约单次往返）→ 未命中再 `INSERT ... ON CONFLICT (id) DO NOTHING` 兜底 → 冲突/插入后补一次 UPDATE：

```sql
UPDATE rt_scheduler_lease SET owner=?, expires_at_ms=?
WHERE id=1 AND (owner=? OR expires_at_ms < ?)
```

**S14 时钟**：注入 SystemClock 时过期比较走数据库时钟（`(EXTRACT(EPOCH FROM NOW())*1000)::BIGINT`，消除跨节点时钟漂移）；TestClock 等保留应用时钟分支。
**P1-2 起租约表增 `leader_epoch`**：换主单调递增，作为控制面 fencing token（副作用前 `isCurrent` 复核）；Placement 表的 epoch 仍独立承担数据面 fencing 语义。

### 3.2 ReconcileLoop（核心调谐循环，约 1000 行）

**字段**：self、leaseStore、registry、capabilityStore、placementStore、engine、planner、commands、migration、**decommission**、config、clock；内部 Map：`lastRebalanceAt`、`lastDrainFailureAt`（排空失败冷却）、`deadSince`（首次观察到死亡时刻，复活即清）、`lastReplicaTopUpAt`、`lastToStopByType`（S5 冻结补偿）。构造器 11 参（注入 NoopDecommissionDriver）与 12 参两版。

**关键常量**：

| 常量 | 值 | 用途 |
|---|---|---|
| `MIGRATION_BATCH_SIZE` | 256 | 分批迁移批大小（批间同步续约） |
| `COMMAND_BATCH_SIZE` | 256 | S4 命令扇出批大小 |
| `COMMAND_TIMEOUT_MS` | 17000（=deadline 5s×3+2s） | 单条命令超时 |
| `COMMAND_POOL_SIZE` / 队列 | 8 / 4096 | 专用 `command-exec-{self}` 守护池（CallerRuns 之外一律记 false；禁 commonPool） |
| `REPLICA_TOP_UP_BATCH_MAX` | 256 | 单周期副本补足上限 |
| `SNAPSHOT_CACHE_TTL_MS` | 1000 | S17 状态快照缓存 |

| 方法 | 行为 |
|---|---|
| `start()` | 幂等；守护线程 `runtime-scheduler-reconcile-{nodeId}` |
| `stop()` | running=false + 中断 + join(2s) + leader=false + commandExecutor.shutdownNow |
| `isLeader()` | 最近一周期的 Leader 身份 |
| `runOnce()` | **单周期入口（boolean：是否以 leader 执行）**：`acquireOrRenewWithEpoch`（记录 leader_epoch）→ leader：**`promoteConfirmedDead()`（多级仲裁 PFAIL→FAIL，先于一切调谐；提升前复核纪元）** → 一次 `capabilityStore.list()` 快照 → `sweepStaleJoiningOrphans()`（§3.12：JOINING 静默 ≥2×TTL 且无任何能力记录 → tombstone，有记录不误伤；逐条前复核纪元）→ 逐类型 reconcile（异常隔离；`stillLeader()` 前置/后置复核覆盖 replaceAll/reassign/migration 各阶段）→ `stillLeader()` 门控的 `decommission.advance()`（每周期末尾，异常 WARN 吞掉）→ 作废快照缓存；失败静默跳过；所有异常吞掉不中断循环 |
| `snapshot()` | `ClusterStatus`（S17，1s TTL 缓存）：`(leader, leaseOwner, capabilities, primariesByCapability, placementsByCapability)`——后者含副本行 `[PRIMARY, REPLICA…]` |
| `stopNode(node, type)` | freeze(false) → stopCapability → setActual(DISABLED) |
| `resetRebalanceCooldown(type)` | 同时清 lastRebalanceAt 与 lastReplicaTopUpAt（仅 leader 实例有效——管理端点"立即重平衡"用） |
| `knownTypes()` | 从 capabilityStore.list() 提取去重排序的 CapabilityType |

**线程模型**：单守护调谐线程；每周期后 `Thread.sleep(min(renewIntervalMs, reconcileIntervalMs))`；命令扇出走专用池。

#### 多级故障确认：`promoteConfirmedDead()`（PFAIL→FAIL）

- 前置：`suspicionStore != null && config.suspicionQuorumEnabled()`（**默认 true**）；仅 leader 执行（租约唯一提升者，天然无 split-brain）；
- 流程：`pruneExpired(ttl)` → `freshVoteCounts(now, ttl)` 读 TTL 内各 suspect 的不同观察者票数 → N=`listAlive()` 快照一次 → 法定人数 `max(suspicionMinObservers, floor((N-1)/2)+1)`（封顶 N-1：2 节点=1、3 节点=2、5 节点=3）→ 票数达阈值且注册表行存活 → `markState(suspect, DEAD)`（epoch+1，状态机校验）并清票；行不存在/已 DEAD → 仅清票；状态机拒绝 → 保留下周期重试；
- 与治愈链路衔接：仲裁 DEAD 与本地直写 DEAD 在注册表中同为 `state=DEAD`，后续 reconcile 的治愈迁移、30s 宽限期、副本提升逻辑零改动；
- 安全特性：非对称分区中单观察者误判（rf=1 时可能导致空迁移永久丢数据）在多数确认下被拦截；leader 故障期间仲裁暂停（故障安全方向，只延迟不误判）。

### 3.3 一轮 reconcile(type) 的六阶段算法

```
阶段1 集合计算：
    alive = registry.listAlive()（权重直接取快照，S7 消除 N+1 点查）；deadSince 保留仍不在 alive 的节点
    desiredOn / actualOn（actual==ACTIVE ∧ alive）/ desiredAlive / capabilityActive（记录口径，迁移端点门控）
    toStart = desiredOn − actualOn ∩ alive；toStop = actualOn − desiredOn

阶段2 放置引导：primaries 为空且 desiredAlive 非空
    → engine.compute(cap, desiredAlive, partitionCount, config.rfFor(cap))
    → placementStore.replaceAll（含 REPLICA 多行，epoch=0）→ 记 lastRebalanceAt

阶段3 冻结补偿（S5，先于上线）：
    leaked = actualOn ∩ desiredOn ∩ lastToStopByType[type]（上周期判待下线、本周期 desired 回改）
    → fanoutCommands freeze(false) 定向解冻；随后 lastToStopByType[type]=toStop

阶段4 待上线：fanoutCommands startCapability → 成功 setActual(ACTIVE)

阶段5 待下线（非空则处理完 return）：
    并行 freeze(true)
    ├─ desiredAlive 为空 → replaceAll(空) 清空放置 + stopNode 排空
    └─ 否则 plan(current, computePrimaries(desiredAlive)) 过滤 from∈toStop：
       · tryPromoteDrainTarget：目标已持该分区 REPLICA → promoteReplica 无损免迁移
         （否则 cutover 撞复合主键——DrainReplicaCollision 复现场景）
       · migrateReady 端点就绪门控：目标能力须 actual=ACTIVE（from 仅存活时要求）
       · 排空失败冷却：lastDrainFailureAt + rebalanceCooldownMs 窗口内保持冻结不重复提交
       · migrateInBatches → stillLeader 复核 → reassignReplicasBatch 副本重排
       · stopNode（freeze(false)→stop→actual=DISABLED）→ 清冷却、更新 lastRebalanceAt

阶段6 治愈或重平衡：
    plan(current, computePrimaries(actualOn))；moves 为空 → topUpReplicas（副本补足，冷却节流）
    (e1) 故障治愈（from ∉ alive，**免比例/冷却门控**——不迁=数据不可用）：
         有存活副本 → tryPromoteLiveReplica（promoteReplica CAS 免迁移）+ 副本集重算
         无存活副本 → healingGracePeriodMs 宽限期：DEAD 持续 < grace 押注重入（"waiting for
                      dead nodes to rejoin"）；≥ grace 才 migrateInBatches（数据丢失窗口 WARN）
         治愈后 return（不占 lastRebalanceAt 预算）
    (e2) 常规扩容重平衡：migrateReady 门控（目标未就绪整周期延后）
         → shouldRebalance(比例 ≥ minMoveRatio 且过 cooldown) → migrateInBatches
         → stillLeader → reassignReplicasBatch → lastRebalanceAt（**失败也记预算**，防任务表爆炸）
```

**migrateInBatches（分批迁移 + 批间续约）**：整批 moves 同步 `migrateAndWait` 可能远超租约 TTL，中途无续约必失租、leader 轮换重复规划（走马灯风暴）。按 256 分批，每批开始前同步 `acquireOrRenewWithEpoch` 并刷新本地纪元；失租立即中止剩余批次（placement epoch fencing 兜底安全）。长操作后 `stillLeader()`（owner + leader_epoch 双校验）复核租约（LeaseSplitBrain 复现场景），失租即自降 leader 身份并中止后续副作用；`replaceAll/reassignReplicasBatch/setActual/markState/tombstone/decommission` 等副作用前均有纪元复核点。

**命令扇出 fanoutCommands（S4）**：8 线程专用池 + `orTimeout(17s)` + 批 256 间同步续约；拒绝/超时/异常一律记 false 下周期重试。

**副本管理动作**（均不动 PRIMARY 不动 epoch，除提升外）：

| 动作 | 触发点 | 行为 |
|---|---|---|
| 副本引导 | 阶段2 | `engine.compute(..., rfFor)` 多行 replaceAll，主+副本一次成环 |
| 副本提升 | 阶段5/6(e1) | `promoteReplica` CAS：REPLICA 升 PRIMARY、删原主行、epoch+1 |
| 副本重置/补足 | 阶段5/6(e2) 迁移后、6 无 moves | `recomputeReplicas` 目标副本 → `reassignReplicasBatch`（新副本数据由能力侧 Replicator 对账补齐）；topUpReplicas 单周期 ≤256 分区 |

### 3.4 DesiredStateWriter

`setDesired(node, type, desired)` 包装 `CapabilityStateStore.setDesired` 并施加集群级校验：

1. desired 只允许 **ACTIVE / DISABLED** 两个开关值；违规抛 IAE；
2. **清空最后节点保护**：操作会导致"desired-ACTIVE 节点数为 0 且仍有 actual-ACTIVE 节点"时抛 `IllegalStateTransitionException`（无处可迁、服务中断）；全部节点已实际停止后允许任意设置（重新启用/排空意图）。

辅助方法：
- `setInitialDesired(node, type, desired): boolean`——**首启引导**：仅当 (node,type) 无记录时写入（actual=DISABLED），已有记录**不覆盖**返回 false（防"UI 禁用→重启被 env 复活"）；
- `isLastDesiredActiveNode(node, type): boolean`——公开判定，供退役预检/准入。

> 无独立 desired_state 表：desired/actual 统一存 `rt_capability_state`（capability 模块）。

### 3.5 NodeCommandChannel（接口）与两个实现

| 方法 | 语义 |
|---|---|
| `boolean startCapability(node, type)` | 远端语义：收敛到 ACTIVE（走 convergeStart） |
| `boolean stopCapability(node, type)` | 收敛到 DISABLED（内部负责 drain 链） |
| `boolean freeze(node, type, frozen)` | 维护开关（不参与状态机） |

约定：失败一律返回 false 不抛异常 → 调度器下周期重试（幂等收敛）。

- **LocalNodeCommandChannel**：仅 node==self 生效，委托进程内 CapabilityManager 的 **convergeStart/convergeStop**（幂等收敛，已 DISABLED 直接 true）。
- **GrpcNodeCommandChannel**（AutoCloseable）：`node==self` 回退 local（不绕网络）；否则从 registry 解析 host:grpcPort（查询异常/未知/端口≤0 → false 不抛，S18），blocking stub 调 ClusterControl（deadline `DEFAULT_DEADLINE_MILLIS=5000ms`，每次调用新建）；plaintext 通道按 `host:port` ConcurrentHashMap 缓存；`StatusRuntimeException` 与一切异常记 warn 返回 false；**A3**：`nodeTargets` 映射 + `evictNode(node)`（NODE_DEAD 事件触发，target 被他节点引用则保留通道）、`cachedChannelCount()` 观测；`close()` 全通道 shutdown + await 2s。

### 3.6 MigrationCoordinator（端口）与 NoopMigrationCoordinator

`boolean migrateAndWait(String capability, List<PartitionMove> moves)`：
- **幂等**（同批 moves 重复执行安全）；**切主职责完全在实现内**（数据搬完调用 `PlacementStore.cutover`/`promoteReplica` CAS）；
- 同步返回：全部完成 true；任一失败 false（调度器保留现状下周期重试）；空 moves 直接 true。

- **NoopMigrationCoordinator**：无数据能力的默认（直接 true，不切主）；真实宿主（server）用 `RuntimeMigrationCoordinator` 委托 `MigrationEngine`。

### 3.7 DecommissionDriver（端口）与 NoopDecommissionDriver

`void advance()`——仅 Leader、每调谐周期末尾调用一次。真实实现 `RuntimeDecommissionCoordinator`（server 模块）推进 `rt_decommission` 记录状态机（见 [10-服务端模块.md](10-服务端模块.md) §5.5）；`NoopDecommissionDriver` 为测试/未装配兜底。scheduler 模块本身无退役表读写。

### 3.8 SchedulerConfig（record，12 字段）

| 参数 | 默认 | 校验 | 含义 |
|---|---|---|---|
| ttlMillis | 10000 | >0 | 租约时长 |
| renewIntervalMs | 3000 | >0 且 < ttl | 续约间隔上限 |
| reconcileIntervalMs | 2000 | >0 | 调谐周期 |
| partitionCount | 4096 | >0 | 分区总数 |
| replicationFactor | 1 | >0 | 每分区副本数（含主）；STORAGE 生产建议 2 |
| cacheReplicationFactor | 1 | >0 | **CACHE 专属副本数**（内存态多副本有幽灵副本代价，默认单副本） |
| minMoveRatio | 0.10 | ∈ (0,1] | 触发扩容重平衡的最小移动比例 |
| rebalanceCooldownMs | 30000 | >=0 | 重平衡/副本补足/排空失败冷却 |
| healingGracePeriodMs | 30000 | >=0 | **治愈宽限期**：无存活副本的 DEAD 分区押注节点重入，超时才降级迁移（副本提升不受此约束） |
| suspicionVoteTtlMs | 12000 | >0 | 怀疑票有效期：超期未刷新的票不计入法定人数 |
| suspicionMinObservers | 1 | >=1 | 法定人数下限；阈值=max(下限, floor((N-1)/2)+1) |
| suspicionQuorumEnabled | true | — | 多数仲裁 DEAD 总开关（2026-10-20 起默认开）；关闭时本类不读票表（传统本地直写语义） |

工厂：9 参兼容构造器（仲裁关闭默认值）与 12 参全参构造器并存。方法 `rfFor(capability)`："CACHE"→cacheReplicationFactor，其余→replicationFactor。`RuntimeProperties` 装配时仲裁默认 true（`RUNTIME_SUSPICION_QUORUM_ENABLED=false` 可回退）。

### 3.9 SchedulerSchema

`bootstrap(DataSource)` 执行 `sql/rt_scheduler.sql`，advisory lock `pg_advisory_lock(4001, 4)` 串行化。
