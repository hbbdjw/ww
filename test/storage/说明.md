# ww storage 分布式对象存储压测脚本（runtime-server 网关版）

基于 **JMeter 5.6.3** 的 `.jmx` 压测脚本，针对 `runtime-server` 暴露的 S3 兼容对象存储 HTTP API（挂载 `/storage`），
对多节点集群（默认 node1/node2/node3）进行存储桶、文件上传、下载、删除、查询等基本功能压测。

> 自 common/storage 合并进 runtime/data 后，admin 侧存储端点已彻底下线。本脚本全部请求改打 runtime-server：
> **无认证**，任意节点可接收请求，网关按 placement 自动路由到分区属主（本机属主直连本地引擎，否则经 gRPC 转发），
> 客户端无需感知集群拓扑。

## 文件清单

| 文件 | 说明 |
| --- | --- |
| `storage-loadtest.jmx` | JMeter 测试计划（可用 JMeter 5.6.3 GUI 打开） |
| `nodes.csv` | 多节点轮询数据源（3 行 `host,port`，施压阶段请求循环轮询） |

## 前置条件

- 集群各节点以 runtime-server 启动，且 STORAGE 能力为 ACTIVE（`runtime.capabilities.storage-desired=true` 或手动 PUT desired）。
- 默认 HTTP 端口为 `SERVER_PORT`（单机 3 节点示例：`SERVER_PORT=8081/8082/8083` + `RUNTIME_NODE_ID=node-1/2/3`）。
- `nodes.csv` 与 TestPlan 变量中的 `NODE*_HOST/PORT` 需与实际节点一致。

## 压测流程

脚本严格按「**清空存储数据 → 施压 → 结果验证**」三段顺序执行（setUp → 主线程组 → tearDown），并已勾选「顺序执行线程组」（`TestPlan.serialize_threadgroups=true`），保证 **上传 → 混合读写 → 删除** 三个施压线程组严格串行：随机下载/HEAD 只会在全部文件上传完成后才发起，不会访问尚未上传的文件。

1. **setUp（清空）**：递归删除 `BUCKET_COUNT` 个测试桶（容忍不存在，204/409 均视为成功）→ 重建 `BUCKET_COUNT` 个测试桶（桶名 `{BUCKET}_1`…`{BUCKET}_N`，建桶经 SyncBucket 广播全集群生效）。
2. **施压**：
   - 上传：并发上传 `FILE_COUNT` 个文件，key 为全数字零填充序号 + `.jpg` 后缀（如 `0000000001.jpg`），按「序号 → 桶」轮询（`((seq-1) % BUCKET_COUNT) + 1`）均匀分布到 N 个桶。
   - 混合读写：随机下载、HEAD 元信息查询（按同序号轮询公式定位桶）、list 随机桶列举。
   - 删除：删除序号 `1..DELETE_COUNT` 的文件（按同公式定位桶）。
3. **tearDown（验证）**：
   - 遍历 `BUCKET_COUNT` 个桶，逐桶 `GET /storage/{bucket}?maxKeys=1000&marker=...` 全量翻页计数并累加（fan-out 列举合并全存活节点视图），比对「累加总数 == 上传成功数 - 删除成功数」（不一致则标记失败）。
   - 对保留区间（`DELETE_COUNT+1 .. FILE_COUNT`）随机抽样下载（按同公式定位桶），断言 HTTP 200，验证「随机请求已上传文件均成功」。

## 覆盖的功能

| 功能 | 端点 | 阶段 |
| --- | --- | --- |
| 存储桶创建 | `PUT /storage/{bucket}`（幂等 + 广播） | setUp |
| 存储桶删除/清空 | `DELETE /storage/{bucket}?recursive=true` | setUp |
| 文件上传 | `PUT /storage/{bucket}/{key}`（流式，网关转发属主） | 施压 |
| 文件下载 | `GET /storage/{bucket}/{key}`（流式 + Range） | 施压 + 验证 |
| 文件删除 | `DELETE /storage/{bucket}/{key}` | 施压 |
| 文件查询（元信息） | `HEAD /storage/{bucket}/{key}` | 施压 |
| 文件查询（列举） | `GET /storage/{bucket}?prefix=&marker=&maxKeys=`（fan-out 合并） | 施压 + 验证计数 |

## 关键参数（Test Plan → 用户定义的变量）

在 JMeter GUI 中打开后可直接修改，无需编辑脚本：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `NODE1_HOST` / `NODE1_PORT` | `127.0.0.1` / `8081` | 节点 1 地址（setUp/tearDown 固定打此节点） |
| `NODE2_HOST` / `NODE2_PORT` | `127.0.0.1` / `8082` | 节点 2 地址 |
| `NODE3_HOST` / `NODE3_PORT` | `127.0.0.1` / `8083` | 节点 3 地址 |
| `BUCKET` | `loadtest` | 压测桶名前缀（实际桶名为 `{BUCKET}_1` … `{BUCKET}_N`，勿与业务桶重名） |
| `BUCKET_COUNT` | `3` | 测试桶数量 N（setUp 创建/清空 N 个桶，上传轮询分布到 N 个桶） |
| `FILE_COUNT` | `1000` | 上传文件总数（每个文件的 key 为全数字零填充序号 + `.jpg` 后缀，内容为同一个实际文件） |
| `UPLOAD_FILE` | `F:\tup\photo_2022-05-05_21-27-28.jpg` | 实际上传文件路径（每次上传读取该文件字节作为请求体） |
| `DELETE_COUNT` | `100` | 删除文件数（须 ≤ `FILE_COUNT`） |
| `KEY_DIGITS` | `10` | 文件序号零填充位数（默认 10 位） |
| `UPLOAD_THREADS` | `10` | 上传并发线程数 |
| `MIX_THREADS` / `MIX_LOOPS` | `10` / `100` | 混合读写并发线程数 / 每线程循环次数 |
| `DEL_THREADS` | `5` | 删除并发线程数 |
| `VERIFY_SAMPLES` | `20` | 验证阶段随机下载抽样次数 |

> **注意**：`KEY_DIGITS` 默认 10，序号计数器（`CounterConfig.format`）与三个随机 key 生成脚本（JSR223）均按该位数零填充。
> 若修改 `KEY_DIGITS`，请同步修改两个计数器（上传/删除）的 `CounterConfig.format` 为对应数量的 `0`。
> `DELETE_COUNT` 须 `≤ FILE_COUNT`，否则验证阶段随机下载区间为空。

## 使用方式

### GUI 打开（可视化）

1. 安装并启动 JMeter 5.6.3。
2. `File → Open`，选择 `test/storage/storage-loadtest.jmx`。
3. 在「用户定义的变量」中按需修改节点地址、规模参数。
4. 点击绿色「启动」按钮运行；用「察看结果树」「汇总报告」查看请求明细与断言结果。

### 命令行（非 GUI）

```bash
# 在 test/storage/ 目录下执行（nodes.csv 使用相对路径，须与 jmx 同目录）
jmeter -n -t storage-loadtest.jmx -l result.jtl -e -o report
```

- `-n`：非 GUI 模式；`-l result.jtl`：保存结果；`-e -o report`：生成 HTML 报告。
- 结果验证结论（list 计数、上传成功数、删除成功数、期望数、是否一致）打印在 `jmeter.log` 与控制台。

## 多节点说明

- 施压阶段（上传/下载/HEAD/list/删除）通过 `nodes.csv` + `CSV Data Set Config`（`shareMode.all` + 循环读取）把请求循环分发到 3 个节点——任一节点都能受理任意 key 的请求（网关自动转发到属主），轮询分发用于压满各节点入口。
- setUp / tearDown 固定打 node1（`NODE1_HOST:NODE1_PORT`）：清空/重建桶、list 翻页计数。
- 若集群只有 1~2 个节点，删减 `nodes.csv` 行即可；若节点地址变化，改 `nodes.csv` 与变量中的 `NODE*_HOST/PORT`。

## 结果判定

- **文件数一致性**：`tearDown` 中 JSR223 采样器逐桶 list 翻页计数（`truncated`/`nextMarker` 驱动分页），比对 `实际总数` 与「上传成功数（HTTP 200）− 删除成功数（HTTP 204）」，不一致时该采样器标记失败并在响应消息中给出明细。
- **随机下载验证**：保留区间随机抽样 `VERIFY_SAMPLES` 次，每次断言 HTTP 200，任一失败即体现在结果树/报告中。
- 建桶/上传/列举等 JSON 接口用 JSR223 断言校验响应体（`"created":true` / `"etag":` / `"objects":`），下载/HEAD/删除用响应码断言（200/200/204），任一失败会在聚合报告中体现。

## 注意事项 / 验证边界

- 本机未安装 JMeter，脚本已通过 XML well-formed 与元素结构校验（元素齐全、无遗留占位符），最终请在实际 JMeter 5.6.3 GUI/命令行下加载运行确认。
- 验证阶段随机下载假设上传阶段基本全成功；若上传存在失败（序号在保留区间内），对应随机下载会 404 并计入失败，属预期暴露问题。
- 删除阶段删除的是序号 `1..DELETE_COUNT`（最早一批），删除成功按 HTTP 204 计数；删除失败（非 204）不改变文件数等式。
- 上传为实际二进制文件（默认 `UPLOAD_FILE` 指向的 jpg）：JSR223 前置处理器读取文件字节并以 ISO-8859-1 转成请求体字符串，上传请求 `contentEncoding=ISO-8859-1` 保证字节无损还原，`Content-Type: image/jpeg` 记录到对象元数据；换文件只需改 `UPLOAD_FILE` 变量（Windows 路径可用 `\` 或 `/`）。
- 写请求在属主节点做 fencing（非属主/纪元过期返回 409），压测期间若发生 rebalance/迁移，少量 409/503 属预期，可在结果树中观察重试策略。
